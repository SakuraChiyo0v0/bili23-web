> 基于《original-ui-baseline.md》（原版 UI/交互 1:1 复刻基准）与已确认产品决策（§15：结构 1:1、可 Web 化动效配色；

> 与后端 API 的映射、移动端落地顺序、里程碑。

## 1. 目标与非目标

### 目标
- 一份可直接开工的前端设计：从“界面抄原版”推进到“知道用什么组件、放哪个目录、状态从哪来、怎么响应式”。
- 说明：**旧版前端备份（backup/frontend-20260904）已废弃，不作为参考或复用来源**；一切以原版 PyQt 基线 + 后端 API 为准。
- 明确需要前后端协作补齐的差距（任务状态机、命名/编号/附加内容 DTO、SSE 语义等）。

### 非目标
- 不写最终像素/色彩稿（进入视觉设计阶段再做）。
- 不绑定具体 UI 组件库实现（给出候选并说明取舍）。
- 不替代《original-ui-baseline.md》——本文引用它，不复述全部交互。

## 2. 现状盘点（已核实）

### 2.1 当前仓库形态
- monorepo（pnpm workspace）：`packages/engine`（纯 TS 下载引擎）+ `apps/web`（Hono REST/SSE 后端）。
- `apps/web` 目前只有 server；**无前端产物**。`/` 与静态资源不托管，只有 `/api/*`。
- 旧版前端在分支 `backup/frontend-20260904`（React 18 + Vite + 手写 CSS）。**已确认废弃：不参考、不复用、不移植。**

### 2.2 旧前端状态（已确认废弃）
| 项 | 旧前端情况 | 结论 |
|---|---|---|
| 页面骨架 | 三 view（parse/tasks/settings）+ hash 切换，缺大量 1:1 交互 | **废弃，不参考** |
| 视觉 | 自定义 CSS（B站粉/青色系、圆角、浅色） | **废弃，不参考**；配色/主题需重新设计 |
| 交互 | 简单，未到 1:1 | **废弃，不参考** |
| 状态 | 简单调用后端 | **废弃，不参考** |
| 登录 | 有扫码/登录雏形 | **废弃，不参考**（按决策重做扫码+Cookie） |

> 结论：**旧前端整体废弃，不作为任何参考/复用来源。** Web 前端从零按《original-ui-baseline.md》+ 本方案 + 后端 API 重建。

### 2.3 后端现状与前端差距（需要协作补齐）
后端（download-manager.ts）已有：
- `POST /api/parse`（解析会话）、`GET /api/media/:itemId`（媒体候选）
- `POST /api/download` + 任务暂停/继续/重试/取消/删除 + `GET /api/tasks/:id/events` SSE
- `config`（全局设置）、`auth`（SESSDATA + 二维码）
- `DownloadOptions` 覆盖：画质/音质/编码/容器/下载视频音频/合并/保留原文件/优先级/附加内容/命名

需要前端设计时对齐/确认的差距：
1. **任务状态机**：后端 `TaskStatus = queued|parsing|downloading|merging|paused|interrupted|completed|failed|cancelled`；
   原版有 `FFMPEG_QUEUED / CONVERTING / ADDITIONAL_PROCESSING / INVALID` 等更细状态。前端 1:1 文案/图标需做映射（方案见 §6.4）。
2. **SSE 事件粒度**：是否推送 `paused/interrupted/ffmpeg阶段`、文件级进度、任务日志；需与后端约定字段。
3. **解析结果的“树形”与“可再解析容器”**：后端 parse 返回的是平铺 item 还是树？原版 NEED_PARSE 行（空间/收藏夹）需要“再解析”动作。需确认 `POST /api/parse` 对空间/收藏夹返回结构是否已含可再解析子列表，或前端需再次调用。
4. **配置项**：是否覆盖全部设置字段（尤其命名规则编辑器、列显隐、自动勾选条件、CDN 列表、字幕语言/样式）。
5. **文件浏览/下载**：`GET /api/files` 已有，但原版“打开目录”/“查看封面”等文件类动作需前端组合。

## 3. 技术栈取舍（建议，可再议）

### 3.1 结论先行
建议采用 **TypeScript + React 18 + Vite** 单页应用；样式用 **CSS Modules + CSS 变量 + 媒体查询**（不引入重型组件库），状态用轻量方案。

理由：
- React + Vite 是当前建议的技术栈（与是否保留旧前端无关）；不引用旧前端代码/样式。
- 后端纯 Hono REST/SSE，无 SSR 需求，适合 SPA + hash 路由（NAS 静态托管简单）。
- 需要大量自绘（树、卡片、自绘组件）与细粒度动效，重组件库（AntD/MUI）反而难贴原版 Fluent 质感与 1:1 布局。

### 3.2 组件库/样式取舍
| 方案 | 优点 | 缺点 | 判断 |
|---|---|---|---|
| 纯手写 CSS + 基础组件 | 完全可控、贴合原版、体积小 | 开发量大 | **推荐** |
| Tailwind | 快速 | 语义化弱、主题定制复杂 | 可不选，若团队偏好可作辅助 |
| AntD/MUI | 现成 | 偏离 Fluent/原版、难做树三态与自绘卡片 | 不推荐作为主 UI |
| shadcn/ui | 较可控 | 仍偏 Web 通用风 | 备选 |

> CSS 变量做主题 token（浅/深/强调色），与旧 `styles.css` 思路一致但要扩展为完整 design token（§5）。

### 3.3 路由
- 桌面：左侧导航（类原版）。
- 移动：底部 TabBar + 抽屉/全屏 Sheet。
- 用 hash 路由（如 `#/parse`、`#/downloads`、`#/settings`）兼顾静态托管与返回键。
- 收藏夹/关于/头像作为“入口”，打开 Flyout/弹窗，不占独立路由（对齐原版）。
- 弹窗类（下载选项、登录、各设置子弹窗）用组件内 state 驱动，不进路由。

### 3.4 状态管理
- 任务列表/配置/登录态属于**跨页面共享状态**：
  - 建议 `zustand`（轻量、TS 友好）或 React Context + useReducer。
  - 任务进度由 **SSE 事件流**写入 store；页面只读 store。
- 解析结果树属于**页面局部状态**，留在 ParseView 内（可配合树形 reducer）。
- 全局 Toast、弹窗、主题：轻量 store/context。

## 5. 设计系统 / 主题 token

### 5.1 范围
- 用 CSS 变量定义 token，覆盖浅/深两套主题 + 强调色（accent）。
- 配色与主题**重新设计**（不复用旧前端色板）；默认主题可再议。

### 5.2 建议 token 分组
| 组 | 示例 |
|---|---|
| 色板 | `--bg` `--surface` `--surface-2/3` `--ink` `--muted` `--line` `--brand` `--success/warning/danger` + 暗色对应 |
| 圆角 | `--radius-sm/md/lg`（基线卡片圆角化层级） |
| 阴影 | `--shadow-sm/md/lg` |
| 间距 | `--space-1..8` |
| 动效 | `--dur-fast/normal/slow`、`--ease-*`；提供 `prefers-reduced-motion` 降级 |
| 字体 | 系统字体栈 + 等宽 |

### 5.3 响应式设计基线
- 断点：`--bp-lg`(≥1024) / `--bp-md`(≥768) / `--bp-sm`(<768)。具体数值视觉阶段可调。
- 移动优先原则：先写移动布局，桌面通过断点增强。
- 触控目标：交互控件最小 44px 高/宽；仅作装饰的元素可小。

## 6. 页面与交互层设计（对齐基线章节）

### 6.1 App 布局与导航
- `App.tsx`：
  - 桌面（≥1024）：左侧固定导航（解析/下载/收藏夹/关于/头像/设置），右侧内容路由。
  - 平板（768–1023）：窄侧栏或底部栏（实现定）。
  - 手机（<768）：底部 TabBar（解析/下载/设置）+ 顶栏（头像/更多）。
- 全局元素：
  - Toast 宿主（顶部短通知 + 右下长消息，§4.2）。
  - “使用协议”首次弹窗；接受后写入配置。
  - 登录弹窗、用户卡片（Flyout）、收藏夹 Flyout、关于弹窗。
- 路由与返回键联动：手机端 Tab 切换支持浏览器返回（见 §17.9）。

### 6.2 登录 / 用户（对齐基线 §12）
- LoginDialog（无短信）：左侧扫码（二维码+状态），右侧 Cookie 登录入口。
- ProfileCard：头像/昵称/UID/打开主页/退出。
- 登录态 store：`auth.status`；未登录访问需登录能力时跳提示（原版 Toast + 请先登录）。

### 6.3 收藏夹与追番（对齐基线 §6 / §12）
- FavoritesFlyout：进入即拉取（需登录）；未登录弹“请先登录”。
- 两个 Tab：我的收藏夹（宫格）+ 追番/追剧（列表带筛选 类型/状态 + 分页）。
- 点击收藏/剧集 → 关闭 Flyout → 跳解析页并解析该 URL。

### 6.4 任务状态映射（后端 TaskStatus → 前端展示）
| 后端 status | 前端图标/主按钮 | 文案 | 备注 |
|---|---|---|---|
| queued | play | 排队中 | 若需区分原版 FFMPEG_QUEUED，需后端给阶段 |
| parsing | (spinner) | 解析中 | |
| downloading | pause | 速度 | |
| merging | (stop/禁用) | 合并中 x% | 映射原版 MERGING |
| paused | play | 已暂停 | |
| interrupted | play | 已中断（可继续） | 原版无此态，Web 可新增展示 |
| completed | open | 已完成 | |
| failed | retry | 失败 | |
| cancelled | (—) | 已取消 | Web 特有；原版删除即移除，需决定是否短暂显示 |
- 若需要显示原版 `CONVERTING / ADDITIONAL_PROCESSING`：前端先按后端**阶段子状态**（如 `phase: "ffmpeg"|"extra"`）设计，后端补齐后再映射文案。
- 前端 UI 不要硬编码后端字符串文案，使用状态→文案映射表。

### 6.5 解析页（对齐基线 §6）——前端最复杂模块
状态：`idle / parsing / success / error`；解析会话对象包含树。
组件树建议：
```
ParseView
  ParseInputBar      // 链接输入 + Parse 下拉(Batch) 
  ParseToolbar       // 数量/搜索/历史/批量选/下载选项
  ParseTree          // 虚拟滚动树（三态勾选 + 列头）
    TreeRow          // 展开/勾选/列单元格/行尾操作
    RowActionMenu    // hover(桌面) / 更多(移动) / 右键
  ParseFooter        // Pager / 搜索结果条 / 季选择 / 进度 / 下载按钮
```
关键实现点：
- 树数据用扁平化数组 + `parentId`，支持增量追加（自动分页/互动 BFS），虚拟滚动。
- 勾选状态放每个 node（三态）；勾选/展开变更走 reducer 重算父节点状态。
- 媒体预览与“下载选项弹窗”数据源：后端 `GET /api/media/:itemId`；选中的多个 item 下载时逐项创建任务。
- 自动勾选、Shift 范围勾选、搜索高亮、批量选择行号、自动分页弹窗、互动视频确认弹窗，均对齐基线 §6。

### 6.6 下载页（对齐基线 §8/§9）
- 双 Tab：Downloading / Completed。
- 顶部批量按钮按 Tab 切换（对齐基线 §8.2）。
- 任务列表 = store 中任务 + SSE 实时更新。
- 任务卡片：封面前提是后端有 cover URL 字段；若无则显示占位。
- 排序偏好、删除/重试/暂停/继续/重解析入口齐全。

### 6.7 设置页（对齐基线 §11）
- 滚动分组卡片（桌面） / 单列卡片（移动）。
- 每一组一个独立 Feature 组件；字段直接绑定 config store（`GET/PUT /api/config`）。
- 命名规则编辑器、CDN/代理/UA、弹幕/字幕样式为独立子组件（可弹窗或页面内展开）。

### 6.8 下载选项弹窗（对齐基线 §7）
- 桌面：750 宽模态三页签。
- 手机：全屏 Sheet / 步骤式三页，预览条吸底。
- 数据流：打开时拉 `GET /api/media/:itemId` 得到候选 → 填入表单 → 保存时（若后端要求）组装 `DownloadOptions` + 调 `POST /api/download`；若后端支持“只保存默认选项”，则写 `PUT /api/config`。
- 强提示（无声/不合并）在确认前出现。

## 7. 弹窗 / Sheet 体系

### 7.1 通用宿主
- 一个全局 `ModalHost`（桌面居中模态 / 手机底部 Sheet 或全屏）。
- 提供：标题栏（Fluent 风格，可自定义按钮）、Esc/遮罩关闭、`stay-on-top` 等价（modal 始终最上）、关闭清理。
- 弹窗尺寸：桌面按原版固定或相对；移动全宽。

### 7.2 弹窗清单（来自基线 §10，标注移动形态）
| 弹窗 | 桌面 | 手机 |

| 重复下载 | 小模态 | Sheet/居中 |
| 分P多P列表 | 树形模态 | 全屏列表 |
| 互动视频确认 | 小模态 | Sheet |
| 查看封面 | 独立小窗 | 全屏图片预览 |

## 8. 动效策略（Web 增强点）

- 页面切换：内容区淡入/轻微位移（桌面侧栏切换；移动 Tab 切换）——可选。
- 卡片 hover / active / 选中：背景与阴影过渡（`--dur-fast`）。
- 列表项进入：底部淡入上移（轻量，批量场景关掉）。
- Toast：滑入 + 自动消失。
- Flyout / 弹窗：缩放 + 淡入（对齐原版 FlyoutAnimationType）。
- 树行展开/收起：高度过渡（限制行数，防止大列表卡顿）。
- **尊重 `prefers-reduced-motion`**：全部动效可关/减弱。

## 10. 后端协作接口清单（前端开工前需确认/补齐）

> 这些不阻塞先搭 UI 骨架，但会阻塞“真功能联调”。前端方案据此提前暴露。

1. **解析树结构与“再解析”**
   - 后端 `POST /api/parse` 返回的是否已含容器行的“再次解析”所需 id/url？需要定义：一次解析返回 item 列表时，哪些 item 仍属容器（空间行/收藏夹行/合集），前端如何触发再次解析并合并/替换子树。
2. **任务状态机字段**
   - 需要 `phase`/`subStatus`（如 `ffmpegQueued/merging/converting/addingExtras`）或由后端扩充 TaskStatus，前端才能显示原版“等待 FFmpeg/转换/附加处理”文案与禁用逻辑。
3. **SSE 事件协议**
   - 约定事件类型：`task:created/updated/deleted`、`task:log`；每事件载荷字段（status/progress/speed/eta/file 级？）。
   - 是否推送历史完成（completed 列表）事件，前端才能同步 Completed 页签。
4. **Cover/缩略图**
   - 任务摘要是否需要 cover 字段（封面 URL）；`/api/files` 是否需要缩略图端点或前端直接引用远程 URL。
5. **命名/编号/附加内容 DTO**
   - 前端命名规则编辑器需要 `GET/PUT /api/config` 支持 naming 规则 CRUD（列表/字段/默认规则/变量说明），以及编号模式字段。
6. **自动选择/解析列表列设置**
   - 是否需要在 config API 暴露 autoSelect 条件与 parse list 列显隐/排序，供设置页读写。
7. **扫码登录**
   - 二维码图片 URL 与轮询端点、登录成功后的用户信息（uname/uid/avatar）与登出入口。
8. **文件浏览增强**
   - “打开下载目录”“打开文件位置”在 Web 上如何呈现：需要 `/api/files` 返回目录/层级 + 提供“在浏览器中浏览目录”页面，或仅“下载文件/复制路径”。

## 11. 分阶段实施（里程碑）

> 每阶段可独立上线验证，均以基线 §16 验收清单为参照。

### P0 工程骨架
- Vite+React 脚手架接入 apps/web；hash 路由；桌面侧栏+移动底栏空布局；主题 token + Toast + 使用协议。
- 验收：桌面/手机两种视口都能看到空壳导航与协议弹窗。

### P1 解析主链路
- 解析输入框→调用 parse→树展示（三态勾选）→批量创建下载→跳下载页；错误 Toast。
- 桌面优先；移动树两列降级。
- 验收：能解析一个视频并完成一次下载（复用后端）。

### P2 下载/任务页
- 双 Tab 任务列表 + SSE 实时进度；暂停/继续/重试/取消/删除；排序；批量开始/暂停/清空。
- 验收：可完整看任务从排队到完成全过程，可断点恢复。

### P3 下载选项弹窗 + 媒体预览
- DownloadOptions 三页 + 实时规格预览条 + 强提示；手机三步骤 Sheet。
- 验收：与基线 §7 逐项一致；手机端选项不丢。

### P4 设置页全量
- 全部 §11 设置分组；命名规则编辑器；CDN/代理/UA/样式弹窗；配置读写。
- 验收：设置字段与基线全对齐，移动端可用。

### P5 登录/收藏夹/关于/协议等入口
- 扫码 + Cookie 登录；用户卡；收藏夹/追番 Flyout；关于/协议。
- 验收：登录后可解析历史/稍后再看/收藏夹；未登录有引导。

### P6 补齐细节 + 移动端打磨

## 12. 开放问题（需下一步决策，不阻塞 P0）

1. **任务状态机是“后端补全”还是“前端映射”**：见 §10.2。倾向后端补一个 phase 字段，前端做文案映射。
2. **配色/主题**：需出新的色板（不复用旧前端粉青）。具体待视觉稿。
3. **组件库最终取舍**：纯 CSS vs Tailwind（可混合：Tailwind 仅作原子类 + CSS 变量 token）。
4. **路由粒度**：弹窗是否进路由（建议不进）；收藏夹是否独立路由（建议仍用 Flyout/Sheet）。
5. **首版语言**：界面文案先用中文还是做 i18n 骨架（原版三语；Web 若后续要国际化，建议 P0 就按 i18n key 组织）。
