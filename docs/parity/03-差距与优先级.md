# bili23-web 功能差距与优先级

> 两份调研的合成结果：
> - **原版有什么** → [`01-原版功能清单.md`](./01-原版功能清单.md)（以原版源码为准，每条带 `文件:行号`）
> - **现在有什么** → [`02-现状功能清单.md`](./02-现状功能清单.md)（以现有代码为准，含"假的"自查）
>
> 目标口径（用户确认）：**功能 1:1 覆盖**、**展示方式与原版一致**；UI 允许因响应式而不同，**不追求像素级一致**。
> 原版基准：Bili23-Downloader v2.15.0。
>
> ⚠️ **本文是当时的快照，行内不改写。** 之后补上的项记在文末「后记：实现进展」。

## 一、量化总览（两份细化对账的实测数字）

| 维度 | 总数 | 已对齐 | 半成品 | **完全没有** |
|---|---|---|---|---|
| **配置项**（`04-配置项对账.md`） | 100（97 ConfigItem + 3 继承 key） | 62 生效 | 1 假（`language`）+ 1 有字段无界面（字幕语言） | **36** |
| **弹窗 / 菜单 / 浮层**（`05-弹窗对账.md`） | 108 | 7 等价 | 31 简化 + 13 位置不同 | **54** |

> 配置项这块的"假"只有 **1 处**（语言，因为没做 i18n）——缺口主要是"**根本没有**"。
> 弹窗这块则相反：**一半（54/108）完全不存在**。

### 五个最要紧的硬缺口（都来自 `05`）

1. **分页体系整块没有** —— 自动解析分页弹窗、搜索范围二选一、跳页弹窗、底部组件切换、教学气泡。
   后端 `ParseResult.pagination` **早就算好了，前端从不读**，解析页只有一个"翻页数"输入框。
2. **解析结果的默认勾选行为与原版相反** —— 原版默认按内容类型**条件式自动勾选**；
   现在 `buildTree` 一律 `checked:false`，**默认一条不勾**。
   （缺的是「自动选择下载项设置」和「剪贴板监控设置」两个弹窗）
3. **行上悬浮命令条整条不存在**（解析此项 / 查看分P列表 / 下载为单个视频 + 显示开关）。
4. **解析页右键菜单叶子专属 6 项全缺** —— 解析此项、在浏览器中打开、下载为单个视频、
   更新媒体信息、查看元数据、查看封面。现有右键只有"仅勾选此项 / 下载此项 / 复制链接"。
5. **应用级日志查看器缺**，且后端**没有任何日志文件写入**（只有每任务 ≤200 行的内存日志）。

### `05` 顺带查出的几个具体 bug

- 任务卡「打开」按**文件名模糊匹配**产物（`TaskActions.tsx:34-43`）—— 重名或多目录时会打开错文件，应改用 `outputPath`
- 下载页两个页签**共用同一套排序项**，而原版"已完成"没有"进度/状态"两项
- 「全部开始」缺失（只有"全部继续"，且只覆盖 paused/interrupted）
- 解析历史没有原版的"**仅保留最近 100 条**"裁剪与提示

### 明确排除（不计入统计）

`01` 附录 B 的全部项 + `.ts` 里 4 条 `type="vanished"`。
其中下载页任务行右键的「编辑下载选项」在源码里是**空实现**，互动视频的「不再询问」、
代理的 SOCKS4/5 均已注释 —— **不算功能**。

## 二、一句话结论

**后端/引擎这条线完成度相当高，前端是主要缺口。**
更麻烦的是：现有前端里有一批**"看起来能用、其实是假的"**地方（14 处）——
它们比"缺功能"更危险，因为用的时候才发现没效果，却找不出原因。

## 三、"假的"清单（14 处，最该先修）

这些东西**界面在、接口在，但实际不生效**——用的时候会以为是自己的问题：

1. popular 期数输入框（填了没用）
2. 「保留原始文件的类型」（服务端不读）
3. Cookie 粘贴格式提示（存的不是 SESSDATA）
4. 语言下拉（无 i18n）
5. 画质/音质/编码优先级（只有占位文案）
6. 追番类型筛选（UI 写死 `type=1`，只能看"追番"，看不到电影/纪录片/国创/电视剧/综艺）
7. `{video_codec}` 命名变量（无音频时恒为空）
8. 已完成列表重启后为空
9. 下载历史（有数据没界面）
10. 速度/剩余时间（算了不显示）
11. `pagination`（5 个解析器算了，前端不读）
12. 解析会话（刷新即丢）
13. CDN 编辑器"大陆/海外"两页签（共用一份列表，只切高亮）
14. 重复下载"询问"（部分重复静默跳过）

## 四、优先级建议（请你定）

### 第 0 批 · **假实现**（14 处）
不改的话，功能表上"有"、实际"没有"，后面所有对账都不可信。而且多数是**小改动**。

### 第 1 批 · **展示方式**（你明确要求的第 2 条）
- **多级树 + 容器行可二次解析** ← 这是原版最核心的展示形态，现在是 2 层
- **表头可排序 / 可调宽**

- 任务卡片补齐字段（含速度/剩余时间）

### 第 2 批 · **原版有、现在完全没有的功能**
- **分页器 + 自动解析分页**（解析页在天花板上的能力）
- **下载历史页 + 产物浏览页**（数据都现成，只缺界面）
- **日志页 + 日志落盘**（现在连日志文件都不写）
- 番剧季切换、剪贴板监控、自定义 UA、应用内更新检查
- 画质/音质/编码优先级编辑

- 解析会话持久化

### 第 3 批 · **引擎侧收口**
- CDN 劣质节点过滤与降权
- 弹幕数据源回归 protobuf、ASS 排版对齐
- 收藏夹番剧行、稍后再看番剧行补全

### 待你确认的取舍
- **短信登录**：原版有（要过极验 + 自建本地回调服务）。你之前明确砍掉过，现在还要不要？

- **桌面专属能力**（系统托盘、打开资源管理器、单实例唤醒、崩溃现场记录）：网页端无法等价实现，**建议明确列为不做**，写进文档以免反复讨论。

## 六、⚠️ 复刻时必须**排除**的东西（否则会照着一堆废弃功能去实现）

这是原版调研最容易被忽略的产出：**原版代码里存在但已经不用/被注释掉的功能**。
它们没进 `.ts`（所以不显示给用户），只在代码里躺着。**对账时如果不排除，会凭空多出一批"待补功能"。**

| 废弃项 | 证据 | 说明 |
|---|---|---|
| 直播间解析 | `url_pattern.py:9` 被注释 | 正则表里唯一被注释掉的一行 |
| SOCKS4 / SOCKS5 代理 | `enum.py:70-71`；`proxy.py:42-52` | 本版本**只支持 HTTP 代理** |
| 下载页右键「编辑下载选项」 | `list_view.py:68`；实现是空的 `:196-197` | 菜单项存在、点了没反应 |
| `fix_mp4_box` | `command.py:163-171`；调用点 `merger.py:79-81` 被注释 | 函数在、没人调 |
| `ParserBase.stop_flag` | `base.py:30-31` | 有定义、全仓无读写 |
| 互动视频「不再询问」勾选框 | `interactive_video.py:34,41-42` | 控件在、无消费方 |
| `.ts` 里 `type="vanished"` 的 4 条 | 见 `原版界面文案-按文件.md` 的状态列 | 含 MCP 的「允许下载操作」开关 |

> **另一个坑**：原版下载地址探测的 `min_file_size` **三处不一致**
> （解析预览 10240 / 下载任务 1024 / 函数默认 1024，`preview/worker.py:57`、`download/parse/query_worker.py:28`、`download_url.py:66`）；
> 时间列语义也是**两套逻辑并存**（表头文案按"分类名字符串"切换，取值按 attribute 位决定）。
> 复刻时**必须挑一套并统一**，否则异常数据下会出现前后不一致。

另外，原版配置项有 **3 个 key 的属性名与 key 名不一致**（带尾下划线），解析配置时极易漏：
`auto_select_mode_`、`prefer_cdn_server_provider_`、`auto_parse_teaching_tip_shown_`；
还有 **3 个继承自 qfluentwidgets 且会一并落盘**的 key：`QFluentWidgets.ThemeMode` / `ThemeColor` / `FontFamilies`。

**两个方向性决定**：
1. **协议层用官方 `@modelcontextprotocol/sdk`（1.30.0）+ zod**，不手写 ——
   版本协商/dual-era/请求头一致性是"别人已解决的问题"，手写只换来一堆边界情况。
2. **加了原版没有的 `mcpBindAddress`**：原版硬编码 `127.0.0.1`（桌面只服务本机），
