## 四、桌面交互 → Web 的替代（必须显式设计，不能默认"差不多"）

| 原版交互 | Web 方案 |
|---|---|

## 六、怎么验证响应式（**别用 `--window-size` 截手机宽度**）

原型已验证：`docs/ui-preview/shell.html`（骨架）+ `responsive-preview.html`（预览台）。

### ⚠️ 一个会骗人的坑

**Chrome 的窗口有最小宽度（实测 528px），`--window-size=414` 会被夹住。**

现象：截图仍是 414 宽，但**页面的 `innerWidth` 其实是 528** ——
媒体查询按 528 生效，超出的 114px 被裁掉。

我因为这个**得出过错误结论**：看到底部导航只渲染出两项，就判断"第三项被挤出屏幕"，
还去改了 `min-width`。实际三项都在，只是**第三项在 x352–528，被截图裁掉了**。
（实测数据：同一份 CSS，最小复现页在 `--window-size=414` 与 `375` 下 `innerWidth` 都是 **528**。）

### 正确做法：用 iframe 指定视口

把页面塞进**指定宽度的 iframe** —— iframe 自己的视口宽度就是它的宽度，
媒体查询会据此正确响应；外层浏览器窗口开大即可。

```
responsive-preview.html
  ├─ iframe 1440×860   （桌面）
  ├─ iframe  900×860   （平板）
  └─ iframe  375×760   （手机）
```

并且**把每个 iframe 的真实 `innerWidth` 写回 `document.title`**，
用 `--dump-dom` 读出来核对（需要 `--allow-file-access-from-files` 才能跨 file:// 读 `contentWindow`）：

```
实测输出：iframe 实际视口: #1=1440  #2=900  #3=375   ✓
```

> **教训**：验证窄屏时，**先确认"我看到的宽度"就是"页面以为的宽度"**。
> 截图尺寸不等于视口宽度 —— 这个项目已经栽过一次（把 3/9 误判成 7/9），这是同类。

## 七、⚠️ 另一个会骗人的坑：根 `pnpm check` **不验证前端能否构建**

```jsonc// 根 package.json"check": "pnpm -r typecheck && pnpm -r test && pnpm -r build"   ← 只跑各包的 typecheck/test/build// apps/web/package.json"check": "npm-run-all typecheck test build check:client"        ← 这个才含前端构建"check:client": "tsc --noEmit -p tsconfig.client.json && vite build"
```

**根 `check` 不会触发 `check:client`**，所以 `pnpm check` 全绿**不代表** `apps/web/src/client/**` 能构建 ——
CSS/TSX 的改动可能压根没进 `dist/`，而类型检查与单测都是绿的。

**实测证据**：改完 `tokens.css` 并跑完 `pnpm check`（全绿）后，`dist/client/assets/index-*.css`
里**仍是旧的蓝紫色**、没有新令牌；直到跑
`pnpm --filter @bili23-web/web check`（含 `vite build`）才刷新。

**以后前端改动一律用这条命令验证**：

```bash
pnpm --filter @bili23-web/web check     # typecheck + test + server build + vite build
```

> **教训**：**"检查通过"只说明检查覆盖到的那部分没问题。** 先确认这条检查命令到底跑了什么，
> 再拿它当依据 —— 否则会得到"全绿但产物是旧的"这种最难查的状态。

### 顺带记下我自己在这轮里的两次误判

同一轮里我连续误报了两次，方向还相反，值得记：

1. **真问题**：看到 `dist` 里 CSS 是旧的，判断"改动没进产物" —— 这是**对的**（构建确实没跑）。
2. **假问题**：看到产物里没有 `--win:#f0f4f9`，判断"令牌没进产物" —— 这是**错的**，
   我默认了 CSS 会被压缩掉空格，而这份构建**根本没压缩**（实际是 `--win: #f0f4f9`）。
   换成带空格的形态后全部命中。

**教训**：**匹配串的形态假设，也是"验证装置"的一部分。** 报"缺失"之前，先确认自己找的形态是对的
—— 这和之前"实验没生效却说办法无效""截图裁剪却说元素没渲染"是同一类错误。

### 骨架落地时定下的几件事

1. **颜色不再各维护一份**：`global.css` 的 `--bg / --surface / --ink / --line / …` 现在**桥接到**
   `tokens.css` 的 `--win / --card / --text / …`。
   ⚠️ `--accent` / `--accent-strong` / `--on-accent` / `--radius` / `--font` 由 tokens.css 直接提供，
   **不能在 global.css 里再写 `--accent: var(--accent)`** —— CSS 自定义属性自引用是无效值。
2. **「解析历史」从导航栏移到解析页工具条**：原版它就是 `parse.py:376` 的 `history_btn`，不是导航项。
   导航项集合现在严格等于原版那 6 项（解析·下载·收藏夹·关于 | 头像·设置）。
3. **下载徽章是真的**：条数 = 未完成任务数，0 隐藏、>99 显示 `99+`（对齐原版
   `update_download_btn_badge_info`）。轮询走 `refreshBadge()`，**不碰 `loading`** ——
   否则下载页会被导航栏的轮询带得一直闪"加载中"。
4. **窄屏顶栏放的是两个图标（收藏夹 / 关于），不是一个「更多」菜单**：导航项集合不变，
   少一层嵌套就能达到同样目的。
5. **断点由 980 改为 1024 / 768**，与本文 §二 的表一致。

### 怎么验（别用 `--window-size` 截窄屏）

`docs/ui-preview/shell-live.html` 是骨架的实时验证台：把**真实前端产物**按 1440 / 900 / 375 三档
并排塞进 iframe，并把每个 iframe 的**真实 `innerWidth` 写进页眉** —— 截图自己就是证据。
用法与两个坑（静态目录认 `process.cwd()`、`--headless=new` 下 `--dump-dom` 无输出）见该文件头部注释。
