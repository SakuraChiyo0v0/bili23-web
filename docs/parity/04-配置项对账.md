## 一、判定口径（重要，先看）

| 现状取值 | 判定标准 |
|---|---|
| **有对应设置且生效** | 存在语义对应的设置入口或功能等价开关，且**有真实运行时读取点**（改了界面/行为真的变）。可持久化在 `data/config.json`，也可在 localStorage / 进程内存（此时在"差距"列注明）。 |
| **有设置但不生效（假）** | 界面能改、值也存得下，但**全仓没有任何运行时读取点** → 改了没效果。 |
| **有配置字段但无界面** | `config.json` / 类型定义里有字段（或仅接口层能传），但**设置页没有任何入口**。 |
| **完全没有** | 既无字段、也无界面、也没有等价功能。 |

**可行性取值**：`可原样搬` / `需要改写`（附改法）/ `不适用`（附原因，如桌面专属、依赖本地进程）。

**排除了什么（不算缺失项）**：按 `01` 附录 B，`.ts` 里 4 条 `type="vanished"`（`Edit download options`、`Allow Download Operations` 及其说明、旧版 `MEDIA_INFO_GUIDE`）与代码中被注释掉/未启用的东西（直播间解析、SOCKS4/SOCKS5 代理、任务右键"编辑下载选项"、`fix_mp4_box` 调用、`ParserBase.stop_flag`、互动视频"不再询问"复选框）**都不计入本表任何一行**（这 97 个 key 里没有它们）。另：`proxy_type` 原版的 SOCKS 选项**已废弃**，故本表只按"仅 HTTP 生效"记账；`mcp_enabled` 原版无"允许下载操作"降级开关（`zh_CN.ts:2307,2311` 为 vanished），故本表不列"只读模式"。

**三个属性名与 key 名不一致的坑**（已单独核过，见下）：`auto_select_mode_`、`prefer_cdn_server_provider_`、`auto_parse_teaching_tip_shown_` —— 三者**属性名带尾下划线**，在 `config.py` 里的行号分别是 `:331`、`:395`、`:485`；现状代码里**一个都没有对应字段**（详见各自行）。

### 结论

**未完成的可实现项还剩 3 件**：剪贴板监控族（1 组）、`m4a_to_mp3`、`preallocate_file_space`；
外加 1 条设计选择差异（`config_version`）。其余 23 条"完全没有"均为桌面专属，已逐条给出不做理由。
**2026-09-12（续）** —— C 类再消一项：`m4a_to_mp3` 已实现（仅纯音频流、`-c:a libmp3lame -q:a 2`、
先写临时名再改名、转换失败保留 m4a）。剩余可实现项：**`preallocate_file_space`** 与
**剪贴板监控族**（`monitor_clipboard` / `auto_parse_interval` / `show_auto_parse_dialog` /
`show_download_confirmation_dialog`）。
**2026-09-12（续二）** —— C 类再消一项：`preallocate_file_space` 已落地。

**先纠正我自己的一个预设**：我原以为原版用 `posix_fallocate`（真占块）、Node 只能用
稀疏 `truncate`、因此存在语义差异。**读源码后发现预设是错的** ——
原版 `util/common/io/file.py` 的 `preallocate_file` 是 `f.seek(size-1); f.write(b"\0")`，
**本身就是稀疏预置**，与 `truncate(size)` 语义等价。所以没有差异需要说明。

落点：引擎 `DownloadFileOptions.preallocate`（gate 原有的 `ensureFileSize`）+
`behavior.preallocateFileSpace`（默认 true，与原版一致）+ 「下载处理」卡一行 + 说明弹窗
（正文 = `PREALLOCATE_GUIDE` 的简中译文，含 FAT32/exFAT 警告）。

**剩余可实现项只剩剪贴板监控族**（`monitor_clipboard` / `auto_parse_interval` /
`show_auto_parse_dialog` / `show_download_confirmation_dialog`）。
**2026-09-12（终）** —— **C 类清零**。`monitor_clipboard` 已落地（Web 改写）。

**先纠正归类**：我前几轮把「剪贴板监控族」当成 4 项，取语义后发现
`auto_parse_interval`（默认 2.0，自动解析分页的页间隔）与 `show_auto_parse_dialog`（默认 False，
分页时先弹对话框还是教学气泡）**属于分页功能，不属于剪贴板** —— 只看名字分组会归错。

**Web 改写**：浏览器不能后台轮询系统剪贴板（`readText` 需授权、只在聚焦时才有意义）。
所以改成**页面重新聚焦时读一次**；命中链接**只填入输入框 + 提示**，由用户点「解析」；
**不自动解析、更不自动下载**（剪贴板里什么都可能有）。读失败静默跳过。

**因此 `show_download_confirmation_dialog` 主动不做**：它的语义是"剪贴板触发后自动走一次下载"，
在浏览器里等于"悄悄开始下载"，不可接受。**这是取舍，不是遗漏。**
