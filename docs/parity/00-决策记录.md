## 2026-09-12 · 功能范围与优先级

**用户原话要点**：

> 1. 功能要完全 1:1 还原，保持一致。
> 2. 展示的方式要一致。
> 3. UI 有变、有一点区别是没有问题的。
> —— 我们要的是功能一致，而非 UI 1:1 一模一样，这是没必要的。

补充确认：

| 议题 | 决定 | 说明 |
|---|---|---|
| **改造路线** | **在 `bili23-web` 上改（不新开项目）** | 理由：该项目**引擎侧完成度很高**（分片并发+断点续传、令牌桶限速、WBI 签名、字幕五格式、封面嵌入、章节 ffmetadata、NFO 三结构、13 类命名规则+57 变量+多级目录都是真实实现），缺口几乎全在前端；新开项目多花的时间主要在重搭骨架与重接线，不会多出任何功能。代价是要逐个清掉遗留的"假实现" |
| **前端 UI** | **整体重做**（不是增量修补） | 用户："前端的 UI 也是要整个重做的哈"。现有的顶部导航 + 蓝紫配色那套**不保留**，按下面「视觉与布局基调」重做 |
| 短信登录 | **不做** | 原版有（需过极验 + 自建本地回调服务）。用户明确不要 |
| MCP 服务器 | **做** | 原版有 9 个工具（`parse_url` / `get_episodes` / `list_tasks` / `get_task_status` / `get_login_status` / `create_download` / `pause_task` / `resume_task` / `cancel_task`）。用户："好像问题不大" |
| 桌面专属能力 | **不做** | 系统托盘、打开资源管理器、单实例唤醒、崩溃现场记录、系统文件对话框等 —— 网页端无法等价实现 |
| 优先级排序 | **由实施方决定** | 用户："优先级你自己看着办" |

### 由此确定的优先级
| 批次 | 内容 | 为什么排这个位置 |
|---|---|---|
| **0** | 修 **14 处"假的"**（界面/接口在、实际不生效） | 不修则"功能表上写着有、实际没有"，后续所有对账都不可信；且多数是小改动 |
| **1** | **展示方式**：多级树（容器行可二次解析）、表头排序/调宽、右键菜单补全、行上悬浮条、任务卡片字段 | 用户明确的第 2 条要求 |
| **2** | 原版有、现在完全没有的功能：分页器 + 自动解析分页、下载历史页、产物浏览页、日志页 + 日志落盘、番剧季切换、剪贴板监控、自定义 UA、画质/音质/编码优先级编辑、i18n、解析会话持久化 | |
| **3** | 引擎侧收口：CDN 劣质节点过滤与降权、弹幕数据源与 ASS 排版、收藏夹番剧行/稍后再看番剧行 | |

### 仍然不适用的范围界定

- **不做**：桌面窗口外观的 1:1 复刻（此前投入的像素级还原到此为止）；
  UI 因需兼容手机端与 Web 端（按宽高响应式切换）允许与原版不同。
- **后端不动**：本次改动集中在 `bili23-web`；NAS 上的网关/WebDAV 等服务不在范围内。
