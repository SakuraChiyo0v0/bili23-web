# 第 1 批方案：展示方式与原版对齐

> 依据：`03-差距与优先级.md` 的五个硬缺口 + 用户要求第 2 条「**展示的方式要一致**」。
> 约束：**UI 可以不同**（要兼容手机端与 Web 端、按宽高响应式切换），但**信息怎么组织、怎么呈现**要跟原版一致。
> 所以下面每条都分「**语义上要对齐什么**」和「**Web/触屏怎么落地**」两栏——后者允许与原版不同。

---

## 1. 解析结果的默认勾选（行为差异，优先级最高）

**现状**：`buildTree` 一律 `checked:false` → **解析完一条都不勾**，要用户自己点。
**原版**：三种模式，默认「条件式」，解析完自动帮你勾好。

| 模式 | 行为 |
|---|---|
| 手动 | 不自动勾选 |
| 全选 | 全勾 |
| **条件式（默认）** | 按内容类型分别处理：**投稿视频**看 `user_uploads`（0=只勾链接指向的那个视频 / 1=分P或合集全勾）；**剧集/课程/会员购课程**看 `bangumi`（0=只勾链接指向那一集 / 1=勾「正片」）；**其它类型**看 `other`（1=全勾） |

「正片」的判定原版是硬编码 `根.children[0].children[0]`（第一个章节节点）。

**要做的**
1. 后端/前端加三个设置项（模式 + 三个条件），并加一张设置卡（原版叫「自动选择下载项设置」）
2. 解析成功后按模式与条件计算初始勾选集合
3. **链接指向项**的定位要一并实现（原版按字段比对：视频用 `cid`、番剧/课程用 `ep_id`、会员购课程用 `section_id`）

**Web 落地**：设置卡直接做成设置页里的一个分组；不需要弹窗。

---

## 2. 多级树：容器行 + 二次解析

**现状**：只按 `groupTitle + containerType` 聚成**两层**（组内 1 条时塌缩成叶子）。
**原版**：最多 **4 层**——解析对象 → 章节 → 分P → 可下载叶子；而且某些行（收藏夹/个人空间/历史/稍后再看/合集列表里的「视频行」）带 `NEED_PARSE` 标记，**不能直接下载，要再解析一次**才展开成分P。

**要做的**
1. `buildTree` 改成保留原版的层级语义（章节/分P 是**容器行**，不是叶子）
2. 容器行不可下载（原版：只有叶子且不带 `TREE_NODE` 位才可下载）
3. `NEED_PARSE` 行加「解析此项」动作 → 调后端展开为子节点
4. 勾选联动要能跨多层（现在是两层，逻辑要泛化）

**Web 落地**：层级用缩进表达即可；**窄屏下只显示「标题 + 状态」两列**，层级靠缩进 + 展开箭头保持。

> ⚠️ 这是这批里**改动最大**的一条，会牵动 `useParseSession`、`ParseTree`、后端解析结果结构。
> 建议**单独一步做**，做完先跑通再叠其它。

---

## 3. 表头：可排序 / 可调宽 / 列可配

**现状**：5 列固定，后 3 列只能整体显示/隐藏（一个布尔 `showMeta`），**无排序、无调宽**。
**原版**：列配置是**数组**（`{id, visible, width, order}`），点表头**按列排序整棵树**（递归），列可增删/重排/调宽（「序号」列锁定）。

**要做的**
1. 把 `parseListPrefs` 的单个布尔升级为**列数组**（`{id, visible, width, order}`），落配置
2. 点表头排序：对整棵树递归排序（原版会同时修正持久索引）
3. 列宽可拖拽
4. 列配置界面（原版是「解析列表设置」弹窗：可勾选 + 可拖拽排序列表 + 两个开关）

**Web 落地**：
- 拖拽调宽在触屏上体验差 → **窄屏隐藏拖拽手柄**，改为「紧凑/宽松」两档或直接自适应
- 列配置界面用设置页里的一个区块，不单独做弹窗

---

## 4. 右键菜单补全（叶子专属 6 项）

**现状**：叶子只有「仅勾选此项 / 下载此项 / 复制链接」。
**原版**：全选/取消全选、反选、勾选/取消勾选、**解析此项**、**在浏览器中打开**、**下载为单个视频**、**更新媒体信息**、**查看元数据**、**查看封面**。

**要做的**（按可否落地分）

| 项 | 可行性 |
|---|---|
| 解析此项 / 勾选类 / 反选类 | ✅ 直接做 |
| 在浏览器中打开 | ✅ `window.open`（原版是调系统浏览器，语义等价） |
| 下载为单个视频 | ✅ 打标记 + 命名强制 `{leaf_title}`（命名引擎已支持） |
| 更新媒体信息 | ✅ 调已有的媒体信息接口强制刷新 |
| 查看元数据 | ✅ 弹窗列出 `to_dict()` 字段（原版还把「取消」改成了「复制」） |
| 查看封面 | ⚠️ 原版是独立小窗 + **另存为**；Web 改为弹层预览 +（可选）前端下载 |

**Web 落地**：**触屏没有右键** → 每行加一个**常驻「⋯」按钮**（桌面端仍保留右键菜单），两者共用同一份菜单项定义。

## 5. 行上悬浮命令条

**现状**：整条不存在。
**原版**：悬停叶子行时右侧浮出 3 个动作——解析此项 / 查看分P视频列表（默认禁用，仅收藏夹中的分P视频可用）/ 下载为单个视频；由设置项 `parse_list_show_floating_command_bar` 控制（默认开）。

**Web 落地**：**触屏无 hover** → 与上一条合并成同一个「⋯」按钮（桌面端可以是 hover 浮现、触屏常驻）。
动作集合就是上一条菜单里的三个，**不重复实现**。设置开关保留（开=显示该按钮）。

---

## 6. 任务卡片补齐字段

**现状**：只有大小 / 进度条 / 百分比 / 状态。
**原版**：封面 + 标题 + 副标题（完成时间或信息标签）+ 大小（已下/总量）+ 进度条 + 状态 + 主按钮 + 删除，**含实时速度**。

**要做的**：显示服务端已算好的 `speedBps` / `etaSec`（第 0 批第 9 条已在修），并补齐「已下 / 总量」与主按钮的状态映射。
**Web 落地**：窄屏卡片纵向化，封面缩小或省略。

## 建议的执行顺序

| 步骤 | 内容 | 为什么这个顺序 |
|---|---|---|
| 1 | **默认勾选行为** | 独立、影响手感最大、不牵动树结构 |
| 2 | **多级树 + 二次解析** | 改动最大，单独做 |
| 3 | **表头排序 / 调宽 / 列配置** | 依赖第 2 步的树结构定型 |
| 4 | **右键菜单 + 「⋯」按钮**（含悬浮条动作） | 依赖第 2 步（要有"解析此项"的落点） |
| 5 | **任务卡片字段** | 与上面互不影响，可随时插入 |

---

## 需要留意的风险

- 第 2 步会改**解析结果的数据结构**，而后端 `pagination`、批量解析、下载建任务都依赖它 → 改完必须回归这几条链路
- 表头拖拽调宽在移动端不可用，**不要为一个桌面才有的交互牺牲窄屏布局**
- 原版的「正片」判定是硬编码取第一个章节节点 —— 这是源码事实，**复刻时照抄还是改进，需要你定**（我倾向照抄，先保证行为一致）
