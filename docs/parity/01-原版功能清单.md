## §0 与既有文档的矛盾（以源码为准）

本清单编写期间核对了 `bili23-web/docs/original-ui-baseline.md`，发现以下 6 处与源码冲突，**以源码为准**：

1. **主题色不是「品牌蓝」** —— 原版从不设置默认强调色，继承 qfluentwidgets 默认值 `#009faa`（青绿）。证据：`.venv/Lib/site-packages/qfluentwidgets/common/config.py:270`（`themeColor = ColorConfigItem("QFluentWidgets", "ThemeColor", '#009faa')`）；Bili23 全仓对主题色只有「用户自选」这一条写入路径 —— `src/gui/component/setting/card.py:114,120`。baseline §11.2「主题色 默认 品牌蓝」**错误**。
2. **Downloads 页不是「首次点击才创建」** —— 只有设置页是首次点击懒加载（`src/gui/interface/main_window.py:505-517` + `:536`）；下载页在首屏之后的 `init_deferred_ui()` 里就建好了（`main_window.py:477-487`），由 `init_utils()` 经 `QTimer.singleShot(0, self.init_utils)` 触发（`main_window.py:416` → `:538-541`）。baseline §5.2 **错误**。
3. **查看封面弹窗没有缩放/拖动** —— 只有「另存为」按钮 + 图片标签（`src/gui/dialog/misc/view_cover.py:29-44`），`resizeEvent` 仅按窗口重算缩放（`:72-75`）。baseline §10.10「可缩放/拖动」无源码依据。
4. **Behavior 组没有「下载队列排序」这张卡** —— 设置页 Behavior 只有 3 张卡：ParsingSettingCard / WindowBehaviorSettingCard / DownloadHandlingSettingCard（`src/gui/interface/setting.py:102-104`）。排序偏好在下载页的排序浮窗里改（`src/gui/component/download_list/top_widget.py:204-233`），仅把结果存进 config（`src/gui/interface/download.py:84-105`）。baseline §11.1 把它列进 Behavior 组不准确。
5. **festival / b23 不是「解析类型」** —— 二者只是链接改写器：`url_patterns` 命中后由 `get_redirect_url()` 重写 URL 并**重算** parser_type（`src/util/parse/worker.py:107-120`），而 `get_parser()` 的 match 里**没有** b23/festival 分支（`worker.py:15-62`）。baseline §2.2 把它们与 video/bangumi 并列成解析类型，语义不准。
6. baseline §6.3 引用「见 §8.6」指向解析历史，实际解析历史是 §10.7 —— 纯交叉引用笔误。

（另核对无误的关键项：任务状态 12 个枚举与 baseline §9.1 完全一致 `src/util/common/enum.py:116-133`；`download_thread` 默认 4 范围 1-10 `config.py:354`；`download_parallel` 默认 1 范围 1-10 `config.py:355`；输出容器默认 MP4 `config.py:363`；关闭行为默认「总是询问」`config.py:344`；预分配默认开 `config.py:348`；保存解析历史默认开 `config.py:333`；剪贴板监控默认关 `config.py:329`；Mica 默认关 `config.py:322`。）

## §2 解析页（ParseInterface）

页面文件 `src/gui/interface/parse.py`；树组件 `src/gui/component/parse_list/`。

### 2.1 链接类型全集
判定方式统一为：**按 `url_patterns` 列表顺序逐条 `pattern.search(url)`，命中即返回类型标识**；无域名解析、无兜底默认分支（`src/util/parse/worker.py:64-69`；正则表 `src/util/common/data/url_pattern.py:4-24`）。全部不命中 → 抛 `Invalid link format`=无效的链接（`worker.py:69`；`zh_CN.ts:1655`）。

1. **投稿视频 video** —— `bilibili\.com/video/([a-zA-Z0-9]+)`（`url_pattern.py:5`）；裸 ID `(?:BV|bv|AV|av)(\w+)`（`:21`）；parser `VideoParser`（`worker.py:17-19`；`src/util/parse/parser/video.py:200`）。`av` 号内部换算成 `bvid`（`parser/video.py:220-243`）。
2. **番剧/影视 bangumi** —— `bilibili\.com/bangumi/(play|media)/(ss\d+|ep\d+|md\d+)`（`url_pattern.py:6`）；裸 ID `(ep\d+|ss\d+)|md\d+`（`:22`）；parser `BangumiParser`（`worker.py:21-23`）；分类名由接口 `result.type` 经 `bangumi_type_map` 细分为番剧/电影/纪录片/国创/电视剧/综艺（`parser/bangumi.py:69-70`；`src/util/common/data/bangumi_type.py`）。`md` 需先调 `pgc/review/user` 换 `season_id`（`parser/bangumi.py:24-36`）。
3. **课程 cheese**（分类值 COURSE） —— `bilibili\.com/cheese/play/(ss\d+|ep\d+)`（`url_pattern.py:7`）；parser `CheeseParser`（`worker.py:25-27`）。
4. **会员购商城课程 lesson**（分类值 MALL_COURSE） —— `mall\.bilibili\.com/lesson/play`，**只匹配路径不含任何 id**，四元组从查询串取（`url_pattern.py:8`；`parser/lesson.py:74-87`）；parser `LessonParser`（`worker.py:29-31`）；**需登录**（`parser/lesson.py:64-65`）。
5. **合集/系列 list**（分类值 COLLECTION_LIST） —— `space\.bilibili\.com/(\d+)/lists`（`url_pattern.py:10`）与 `bilibili\.com/list/(\d+)`（`:15`）；parser `ListParser`（`worker.py:41-43`）；再按 `type=season`/`type=series`/`sid=` 分流不同接口（`parser/list.py:41-62`）。
6. **收藏夹 favlist**（分类值 FAVORITES） —— `space\.bilibili\.com/(\d+)/favlist`（`url_pattern.py:11`）与 `www.bilibili\.com/list/ml(\d+)`（`:12`，**这条归 favlist 不归 list**）；parser `FavlistParser`（`worker.py:37-39`）。
7. **个人空间 space**（分类值 PROFILE） —— `space\.bilibili\.com/(\d+)`（`url_pattern.py:13`）与 `www\.bilibili\.com/medialist/play/(\d+)`（`:14`）；mid 只从 `urlparse(url).path` 取，避免查询串关键词干扰（`parser/space.py:19-23`）；parser `SpaceParser`（`worker.py:33-35`）。
8. **每周必看 popular**（分类值 WEEKLY） —— `bilibili\.com/v/popular`（`url_pattern.py:16`）；需带 `num=(\d+)` 期号，缺失抛「无效的链接」（`parser/popular.py:10-13`）；parser `PopularParser`（`worker.py:45-47`）。
9. **稍后再看 watch_later** —— 自定义伪协议 `bili23://watch_later`（`url_pattern.py:17`）；**需登录**（`parser/watch_later.py:20`）；parser `WatchLaterParser`（`worker.py:49-51`）。
   - 网页版注意点：`bili23://` 是桌面自定义协议，Web 端无等价物，需用应用内入口/路由替代。
10. **历史记录 history** —— 自定义伪协议 `bili23://history`（`url_pattern.py:18`）；**需登录**（`parser/history.py:21`）；parser `HistoryParser`（`worker.py:53-55`）。
11. **音频/音乐 audio**（分类值 AUDIO） —— `(am[0-9]+)|(au[0-9]+)`（`url_pattern.py:23`）；parser `AudioParser`（`worker.py:57-59`）；`au` 单曲、`am` 歌单（`parser/audio.py:24-37`）。
12. **活动页 festival**（**仅链接改写**） —— `bilibili\.com/festival`（`url_pattern.py:19`）；抓页面 `window.__INITIAL_STATE__` 里的 `videoInfo.bvid` 改写成 `bilibili.com/video/{bvid}`（`parser/festival.py:21-42`）。
13. **b23 短链**（**仅链接改写**） —— `(b23\.tv|bili2233\.cn)`（`url_pattern.py:20`）；展开见下。
14. **直播间** —— 正则已被注释掉，**当前不支持**（`url_pattern.py:9`）。
15. **互动视频**（**无独立正则**，接口字段判定） —— 视频接口 `rights.is_stein_gate == 1` 时把类型改成 INTERACTIVE_VIDEO 并弹对话框（`parser/video.py:265-268,305-307`）；由 `ProgressParseWorker._get_interactive_video_parser` 单独构造，**不在 `get_parser` 的 match 分支里**（`worker.py:161-175`）。
16. **不经正则的入口** —— `FavoriteParser` 由收藏 Flyout 直接实例化，产出「列表项 dict」而非剧集树（`parser/favorite.py:11-35`；`src/gui/component/widget/flyout.py:282-286`）。

**b23 短链展开流程**
① 取第一个 `https://` 位置规范化（`parser/b23.py:19-30`）② `ResponseType.REDIRECT_URL` 拿最终落地地址（`b23.py:11-12`；`src/util/network/request.py:338-339`，全局 client `follow_redirects=True` 故能到终点 `request.py:194`）③ 展开结果与原 URL 相同 → 报错 `The b23.tv short link is invalid or has expired.`=b23.tv短链接无效或已过期。（`b23.py:14-15`；`zh_CN.ts:1650`）④ 返回新 URL 并重算 parser_type（`worker.py:118-120`）。

**b23 展开的两个源码缺陷（Web 端不必复刻）**
- 触发条件是子串 `"b23" in url`（`worker.py:116-118`），而 `bili2233.cn` 不含连续子串 `b23`，故该域名虽被识别为 b23 却不会展开，会落到 `get_parser` 的 `case _` 抛「未知的解析类型」（`worker.py:61-62`）。
- 同一子串判定会被查询参数里含 `b23`/`festival` 的普通链接误触发。

### 2.2 ParserBase 公共能力（`src/util/parse/parser/base.py`）
- 注意 —— `get_episodes`/`get_additional`/`get_download_url`/`get_cover` **不在基类**。下载地址在 `src/util/parse/preview/worker.py:70` 与 `src/util/download/parse/query_worker.py:30`，封面在 `src/util/download/cover/manager.py`，附加内容在 `src/util/parse/additional/worker.py`。
- `find_str(pattern, url, check=True)` —— 正则取首个结果，取不到且 check 时抛「无效的链接」（`base.py:53-60`）。
- `enc_wbi(params)` —— WBI 签名：64 位混洗表 `mixinKeyEncTab` 重排 `img_key+sub_key` 取前 32 位做 mixin_key，插 `wts`（秒级时间戳）、键名升序排序、剔除 `!'()*`，`w_rid = md5(urlencode(params)+mixin_key)`（`base.py:18-23,62-81`）。
- `check_response(response)` —— `code != 0` 打日志并抛接口 message（`base.py:88-98`）。
- `check_login()` —— 未登录或 `is_expired` 时弹错误 toast + 抛异常，是「需要登录」的唯一公共实现（`base.py:109-117`）。
- `get_extra_data()` —— 默认 `{}`；重写者：bangumi/favlist/history/watch_later/space/list；未重写（即无分页无季）：video/cheese/lesson/popular/audio（`base.py:100-101`）。
- `get_category_name()` —— 默认取 `get_parser_type().value`；BangumiParser 覆写为类型映射（`base.py:106-107`；`parser/bangumi.py:69-70`）。
- `get_url_keyword()` / `set_search_keyword()` —— 从链接取关键词 / 写进 `info_data["data"]["_search_keyword"]` 供标题标注（`base.py:37-51`）。
- `stop_flag` —— 有定义无任何读写点，事实上的死属性（`base.py:30-31`）。

### 2.3 服务端搜索（`src/util/parse/search_url.py`）
- 支持搜索的类型白名单 —— 仅 space/favlist/history 用参数名 `keyword`、watch_later 用 `key`（`search_url.py:8-13`）。
- 不支持者 —— 合集(list)、每周必看(popular) 等接口无搜索参数（`search_url.py:7`）。
- 关键词随链接传递 —— 写回 URL 的查询串，翻页/自动解析分页/解析历史全部复用该链接，无需另存状态（`search_url.py:37-55`）。
- 关键词为空 —— `pop` 掉参数，即恢复完整列表（`search_url.py:52-53`）。

### 2.4 结果树结构
- 层数 —— 最多 4 层可见：**不可见包装根**（`TreeItem({})`）→ 第1层「解析对象本身」→ 第2层「分组（章节/篇章/分区）」→ 第3层「分P」→ 第4层「可下载叶子」（`src/util/parse/episode/base.py:41-47`；`src/util/parse/episode/tree.py:86`）。
- 第2层存在性 —— 合集只有 1 个正片章节时不建「章节」层（`episode/video.py:177-180`）；商城课程 `chapterName` 为空时不建（`episode/lesson.py:50-54`）。
- 各类型树形态 ——
  - 单P视频 —— 2 层：容器 → 1 叶子（`episode/video.py:35-66`）。
  - 分P视频 —— 2 层：「分P」容器 → N 叶子；`?p=N` 只用于定位不改变树形（`episode/video.py:68-105`；`parser/video.py:214-218`）。
  - 合集 —— 2~4 层：合集 →（多章节才有的）章节 →（该稿件多P才有的）分P → 叶子（`episode/video.py:107-216`）。
  - 互动视频 —— 2 层：容器 → BFS 可达节点各一条，增量挂树（`parser/video.py:167-188`；`episode/dynamic.py:115-136`）。
  - 番剧 —— 3 层：季 →「章节」（**恒有**）→ 叶子（`episode/bangumi.py:29-88`）；**支持季切换**。
  - 课程 —— 3 层：课程 →「章节」（空 episodes 的章节跳过）→ 叶子（`episode/cheese.py:28-82`）。
  - 商城课程 —— 2~3 层：课程 →（`chapterName` 非空的）章节 → 小节；未更新或无 `sectionId` 的小节不入树（`episode/lesson.py:29-63,71,122`）。
  - 音频 —— 2 层：歌单名 → 叶子；单曲包成单元素列表复用同一路径（`episode/audio.py:14,23-53`）。
  - 收藏夹 —— 2 层：收藏夹名 → 叶子，叶子一律带 `NEED_PARSE_BIT`，有分页 `ps=40` + 服务端搜索（`episode/favlist.py:23,100`；`parser/favlist.py:13,65-77`）。
  - 合集列表 —— 2 层，`ps=30` + 分页，叶子带 `NEED_PARSE_BIT`（`parser/list.py:13`；`episode/list.py:23-53`）。
  - 个人空间 —— 2 层，`ps=40` + 分页 + 服务端搜索，叶子带 `NEED_PARSE_BIT`（`parser/space.py:17,95-107`）。
  - 每周必看 —— 2 层，无分页无搜索（`episode/popular.py:20-54`）。
  - 历史记录 —— 2 层，`ps=20` + 分页 + `keyword`；无关键词时容器标题留空回退分类名（`parser/history.py:13,36`；`episode/base.py:50`）。
  - 稍后再看 —— 2 层，`ps=20` + 分页，搜索参数名是 `key`（`parser/watch_later.py:12,38`）。
  - 自动解析/批量 —— 在**同一棵树**上追加同层子节点，不新建层级（`episode/dynamic.py:96-111`）。
- 分页元数据 —— `get_extra_data()` 输出 `{pagination, pagination_data{total_pages,total_items,current_page}, server_search, keyword, seasons, season_data}`（`parser/base.py:100`；消费点 `src/gui/interface/parse.py:52-89`）。

### 2.6 勾选体系（全部规则）
- 三态 —— Checked / Unchecked / PartiallyChecked（`tree.py:97`）。
- 父→子 —— 置 Checked 或 Unchecked 时 `_propagate_down` 递归下传全部子孙（`tree.py:117-138`）。
- 子→父 —— `_propagate_up` 全选→Checked、全不选→Unchecked、否则 PartiallyChecked，并继续上溯（`tree.py:140-156`）。
- 半选节点点击 —— `on_toggle_check_state` 中「非 Unchecked 即置 Checked」，故半选→全选（`src/gui/component/parse_list/tree_view.py:611-614`）。
- 全选/全不选 —— 只改根节点状态，子节点自动跟随（`tree_view.py:550-555`）。
- 反选 —— 逐个叶子取反（`tree_view.py:557-563`）。
- **Shift 范围勾选** —— Shift+左键点行任意处即触发，不必命中复选框；以「上次手动点击复选框的项」为锚点，按可见顺序（跳过折叠节内子项、跨展开项）填充锚点状态，折叠节点算整组；锚点为半选时按勾选处理；回拖时用会话快照还原被移出范围的项（`tree_view.py:122-175,236-245`）。
  - 网页版注意点：触屏无 Shift，需另给「全选/反选/批量行号」入口（原版右键菜单与批量选择对话框已有等价能力）。
- 锚点重置时机 —— 模型重置、排序/搜索导致 `layoutChanged` 时清锚点/快照（`tree_view.py:66-68,75-80`）。
- 批量选择 —— 输入「1,3,5-10」等行号，匹配 `item.number` 则勾选（`tree_view.py:721-728`；`src/gui/dialog/misc/batch_select.py:39-53`）。
- 搜索命中项全选 —— SearchWidget「全选」把全部匹配项勾上（`src/gui/component/widget/search.py:79-83`；`tree_view.py:712-716`）。
- 可勾选列 —— 仅第 0 列（序号列）可勾选，其余列只可选（`model.py:268-277`）。
- 勾选收集 —— 只收叶子且 `attribute & TREE_NODE_BIT == 0`（容器不可下载），可顺带置 `downloaded=True`（`tree.py:195-212`）。
- **自动勾选三模式**（`src/util/common/enum.py:170-173`；`src/gui/interface/parse.py:91-134`）
  - MANUAL 手动（值0） —— 不自动勾选，但仍记录「链接指向的项」用于媒体预览定位（`tree_view.py:401-412`）。
  - SELECT_ALL 全选（值1） —— 勾选全部（`parse.py:93-97`）。
  - CONDITIONAL 条件式（值2，**默认**，`config.py:331`） —— 按内容类型分别处理：投稿视频看 `user_uploads`（0=仅链接指向的单个视频，1=分P/合集中全部）；剧集类看 `bangumi`（0=仅链接指向的那一集，1=`_check_main_episodes_node()` 勾正片）；课程/会员购课程看 `bangumi`（1 时全选）；其它类型看 `other`（1 时全选）（`parse.py:99-134`）。
- 「正片」判定 —— 硬编码取 `根.children[0].children[0]`，即第1层下第一个章节节点（`tree_view.py:738-744`）。
- 链接定位 —— 按 `(字段名, 值)` 在全部叶子中比对：视频用 `cid`、番剧/课程用 `ep_id`、商城课程用 `section_id`（`parse.py:404-410`；`tree_view.py:681-710`；`episode/video.py:29`、`episode/bangumi.py:23`、`episode/lesson.py:23`）。
- 预览候选排序 —— 链接指向项为首选，其余按「有 badge（充电专属/付费，多半取不到媒体信息）」排后，最多 3 个候选（`tree_view.py:529-548`）。

### 3.5 暂停 / 恢复 / 重试 / 删除 / 重新下载语义
- 暂停 —— `Downloader.pause()`：提升 generation、置 `_stop_event`、关会话、停测速定时器、补一次落盘；**是断点续传**（分片断点 `chunk_offsets` 随任务快照入库）（`downloader.py:771-783,232-254`）。
- 恢复 —— `resume()` 置 DOWNLOADING 清 stop_event 后 `start()`；`start()` 用已有 queue 过滤，跳过已下好的文件（`downloader.py:785-788`；`parse_worker.py:321-330`）。
- 重试 —— `retry()`：FAILED→`start()`（按已有 queue/断点续下）；FFMPEG_FAILED→`start_merge()`（**不重下**）（`downloader.py:790-795`）。
- 删除 —— COMPLETED 只删数据库记录、**不删文件**；其它状态 = 移出列表 + 删记录 + 后台删除该任务的临时/中间文件；DOWNLOADING 先等分片停；MERGING/CONVERTING **禁止删除**（`model.py:166-182`；`task/manager.py:419-454`；`src/util/common/io/file.py:12-19`）。
- 重新下载 —— COMPLETED：`reset()` 清 queue/files/progress/大小/速度并删临时文件 → 移出完成列表 → `recreate()` 搬回下载表；DOWNLOADING 先暂停；MERGING/CONVERTING 拒绝（`model.py:339-365`；`task/manager.py:474-505`）。
- 「二次解析」（建任务时） —— 带 `NEED_PARSE_BIT` 的条目（收藏夹/个人空间/合集列表/历史/稍后再看）由 `ReparseWorker` 再解析一次，把子节点重新投回 `create_task`（`task/manager.py:174-183`；`task/reparse_worker.py:21-60`；`tree.py:74`）。
- 重复下载判定 —— `_check_duplicate` 按 hash_id 查两表，三选一 CONTINUE/SKIP/ALWAYS_ASK（`task/manager.py:536-573`；`db.py:261-269`）。

### 3.6 限速与并发
- 限速实现 —— 线程安全令牌桶 `TokenBucket`，桶容量=速率，分片每收一块先 `consume` 再写盘，休眠分 0.1s 段以响应暂停（`downloader.py:34-76,317-318`）。
- 限速作用域 —— **每个任务一个桶**，故 `download_parallel > 1` 时总速率可超过设定值；`set_rate` 有定义无调用点（`downloader.py:406-411`）。改动设置只对之后新建的 Downloader 生效。
- 限速默认 —— `speed_limit_enabled` 默认 False、`speed_limit_rate` 默认 10.0（单位 MB/s，范围 0–1000，0=不限速），换算 `rate = 值 × 1024 × 1024`（`config.py:356-357`；`src/gui/dialog/setting/speed_limit.py:20-29,41-43`；`downloader.py:407`）。
- 任务级并发 —— `download_parallel` 默认 1、范围 1–10；调度为单次扫描 source model 的顺序，PARSING 与 DOWNLOADING 都占额度，FFMPEG_QUEUED 不占（`config.py:355`；`model.py:246-272`）。
- 单任务分片线程 —— `download_thread` 默认 4、范围 1–10，用作每任务线程池与 httpx 连接池上限（`config.py:354`；`downloader.py:402-403,942`）。
- 分片大小 —— 硬编码 4 MB，分片数 = `ceil(size/4MB)`（`downloader.py:413,810-814`）。
- 分片断点粒度 —— 每 1MB flush 并记断点（`downloader.py:82`）。
- 合并并发 —— **硬编码上限 1**，其余停在 FFMPEG_QUEUED 由调度器轮流放行（`model.py:287-310`）。
- 调度触发 —— `auto_manage_concurrent_downloads` 信号，延迟到事件循环执行并屏蔽重入（`src/util/common/signal_bus.py:52`；`download.py:70`；`list_view.py:161-171`）。
- 无优先级队列 —— 无 priority 字段，调度顺序即列表顺序（入库顺序），展示排序不影响实际先后（`db.py:150`；`proxy_model.py:293-298`）。

### 7.9 server.py —— 极验回调服务
- 本地 HTTP 服务，**固定 `127.0.0.1:2333`**（`src/util/auth/server.py:127`）。
- 结构 —— `ServerThread`（HTTP 服务）+ `QueueListenerThread`（主进程侧 daemon）+ req/res 队列（`server.py:83-88,114-124,141-161`）。
- `GET /geetest/captcha/init` —— 投 `get_geetest_info`，阻塞等 `geetest_info`（0.1s 轮询、可被 stop_event 打断），JSON 返回 `{challenge, gt}`；其它路径 404（`:19-40`）。
- `POST /geetest/captcha/callback` —— 仅 `Content-Type == "application/json;charset=UTF-8"` 时解析，取 `seccode`/`validate` 投递；一律回 200 `OK`；其它 404（`:42-61`）。
- `OPTIONS` 200 + CORS；所有响应带 `Access-Control-Allow-Origin: *`；屏蔽默认日志（`:12-17,63-73`）。
- 主进程侧 —— `get_geetest_info` → 从 `CaptchaInfo` 回填 `challenge`/`gt`；`captcha_success` → 写 `CaptchaInfo.seccode`/`validate` 并 `signal_bus.login.send_sms.emit()`（注释原文「安全地在主进程触发 Qt 信号」）（`:96-106`）。
- 启停时机 —— `Captcha.init_geetest()` 拿到验证码信息**之后**才启动（注释原文「延迟启动服务器，确保在获取到验证码信息后才启动，避免不必要的资源占用」）；停止于对话框关闭 `login.py:147` 与 `Captcha.cleanup()`（`src/util/auth/captcha.py:24-31,44-50`）。
- 网页版注意点：这是「浏览器内跑极验 → 本地服务收回调」的桌面链路。Web 端短信登录需改为后端 SMS 通道（产品决策已定：Web 只做扫码 + Cookie，短信不做）。

### 7.10 captcha.py + captcha.html —— 极验

- `init_geetest()` → `GET passport.bilibili.com/x/passport-login/captcha?source=main-fe-header&t=0.1867987009754133`（`t` 为**硬编码常量**）；成功写 `data.token`/`data.geetest.challenge`/`data.geetest.gt` → 起本地服务 → `WebPage.open("captcha.html")`（`captcha.py:33-54`）。

- `captcha.html` —— Geetest v0.4.8 官方脚本（文件头注释 `"v0.4.8 Geetest Inc.";`，`:149`）；`onload` → `GET http://localhost:2333/geetest/captcha/init`，失败 `alert("无法与后端通信，验证码初始化失败")`（`:566-577`）；`initGeetest({gt, challenge, offline:false, new_captcha:true, product:"popup", width:"300px", https:true})`（`:579-592`）；成功 → 组装 `{challenge, seccode, validate}` POST 到 `http://localhost:2333/geetest/captcha/callback`，成功 `alert("验证成功，请返回程序继续后续操作")`，失败/`onError` → `alert("无法与后端通信，验证失败")`（`:599-619`）。
- 闭环 —— 获取验证码 → `init_geetest()`（取 token/challenge/gt、起服务、开浏览器）→ 浏览器完成极验 → POST 回调 → 本地服务转主进程 → `send_sms` → `SMS.send()`（带 token/challenge/validate/seccode）→ 返回 `captcha_key` → `sms_sent` → 倒计时；登录时 `SMS.login()` 带 `captcha_key`。
- ⚠ 浏览器上报的 `challenge`（geetest_challenge）**未保存**，发短信用的是接口返回的 `CaptchaInfo.challenge`（`server.py:53-57`；`sms.py:53`）。
- ⚠ 源码级问题（未实测）—— `Captcha(AuthBase)` 未定义 `error` 信号（`captcha.py:17-22`），而 `AuthBase.on_error`/`check_response` 访问 `self.error`（`base.py:17,30`），错误路径会抛 `AttributeError`。

### 8.1 弹幕
- 支持 **3 种**输出格式：XML / ASS / JSON（`src/util/common/enum.py:41-44`）；**默认 ASS**（`config.py:368`）。
- 格式分派 —— `match danmaku_type` → `_to_xml`/`_to_ass`/`_to_json`（`additional/danmaku.py:26-34`）。
- 数据来源 —— B站 protobuf 分段接口 `api.bilibili.com/x/v2/dm/wbi/web/seg.so`（`type=1`、`oid=cid`、`segment_index`），**每 6 分钟一包**（`ceil(duration/360)`），时长缺失则返回空列表（`danmaku.py:67-93`）。
- 反序列化 —— `DmSegMobileReply.ParseFromString` + `MessageToDict`，过滤无 `stime` 或 `text` 的项（`danmaku.py:95-110`）。
- 文件名 —— `<name>.弹幕.<ext>`（`danmaku.py:36`；`src/util/common/translator.py:335`；`zh_CN.ts:8` 弹幕）。

**XML**（`src/util/parse/additional/file/danmaku_xml.py`）
- XML 声明 `encoding="UTF-8"`。
- 固定头 —— `chatserver=chat.bilibili.com` / `chatid={cid}` / `mission=0` / `maxlimit=1500` / `state=0` / `real_name=0` / `source=k-v`（`:5-15`）。
- 每条结构 —— `<d p="{stime},{mode},{size},{color},{date},0,{uhash},{dmid}">{text}</d>`（`:32-47`）。
- `stime` 由毫秒转秒、保留 5 位小数（`:35,64-65`）。
- ⚠ `p` 第 6 位（pool）**硬编码为 0**（proto 里有 `pool` 字段但未使用）；`weight` 作为 `format` 参数传入但模板无该占位符，**实际不生效**（`:34,42`）。
- 文本转义 `& < > " '` 并移除控制字符 `[\x00-\x1F\x7F]`（`:51-62`）。
- 默认值 —— mode=1、size=25、color=16777215（白）、date=0、uhash=0、dmid=0（`:36-42`）。

**ASS**（`src/util/parse/additional/file/danmaku_ass.py`）
- 弹幕按 `stime` 排序（`:138`）。
- Script Info 段 —— `ScriptType: v4.00+` / `WrapStyle: 2` / `Collisions: Normal` / `ScaledBorderAndShadow: yes` / `Aspect Ratio` / `YCbCr Matrix: TV.601` / `PlayResX` / `PlayResY`（`:9-29`）。
- 样式行（V4+ Styles，Name=Default）字段顺序 —— 字体名/字号/主色/次色/描边色/背景色/粗/斜/下划线/删除线/ScaleX=100/ScaleY=100/Spacing=0/Angle=0/BorderStyle=1/Outline/Shadow/Alignment=7/MarginL=R=V=0/Encoding=1（`:172-183`）。
- 透明度 —— `opacity%` → `alpha=(1-opacity)*255`，写入 `&H{alpha}BBGGRR`，主/次/描边/背景 4 色同 alpha（`:168-171`）。
- 字体 —— 在 `QApplication.font()` 上设置 name/size(pixel)/bold/italic/underline/strike，行高 = `QFontMetrics.height()+4`（`:85-95`）。
- 行数 —— 滚动行数 = `int(屏高*display_area/行高)`，顶部/底部固定区行数同上，最小 1（`:97,101-106`）。
- 显示时长（**硬编码，毫秒**）—— mode 1/2/3 滚动=10000、mode 4 底部=5000、mode 5 顶部=5000（`:142-146`）。
- **mode 不在 1..5 的（如代码弹幕/高级弹幕）直接丢弃**（`:194-195`）。
- 滚动弹幕 —— `\move(屏宽, y, -文本宽, y)`，速度 = `(屏宽+文本宽)/时长`（`:109,206-211`）；顶部 `\an8\pos(屏宽/2, y)`（`:213-218`）；底部 `\an2\pos(屏宽/2, 屏高 - row*行高)`（`:220-225`）。
- 轨道分配失败（满屏）则**丢弃该条**防重叠（`:227-228`）。
- 非白色弹幕 —— RGB→BGR 转换后附加 `\c&HBBGGRR&`（`:230-237`）。
- Dialogue 行 —— `Dialogue: 0,{start},{end},Default,,0,0,0,,{...}`（`:239`）。
- 滚动轨道避让两条判据（尾部离开右边缘 + 前一条尾巴到左边缘时后一条头未到）（`:40-50`）。
- 时间格式 —— ASS `h:mm:ss.cc`（`src/util/format/time.py:69-79`）。
- 默认样式值 —— 黑体 36、border 1.0、shadow 0、display_area 60%、opacity 80%、scroll_duration 10s、static_duration 5s、minimum_gap 100px、分辨率 1280×720（`config.py:102-126`）。
- GUI 可调范围 —— 字号 1–1000、display_area 10–100、opacity 10–100、滚动/固定时长 3–15s、最小间距 0–300px、分辨率 1–10000（`src/gui/component/setting/group.py:26,237,242,247,252,257,299,307`）。
- ⚠ **两处源码事实** —— ① `scroll_duration`/`static_duration` 在 config 有默认值、GUI 可调（3–15s），但 ASS 生成代码**未读取**，用的是硬编码 10s/5s（`config.py:118-119`；`group.py:276-285` vs `danmaku_ass.py:142-146`）② **无屏蔽词过滤、无正则过滤** —— 附加模块与配置项中不存在任何弹幕关键词/正则过滤实现；`danmaku_speed_map`/`danmaku_density_map` 也无任何消费方（`src/util/common/data/danmaku.py:1-13`）。

**JSON** —— `json_dumps(dict_list, indent=2)`，即 protobuf 转 dict 后的数组（`danmaku.py:64-65`）。

**弹幕嵌入**
- 仅 ASS 格式、`embed_danmaku` 开启、且输出容器为 MKV 时登记为字幕轨；其余情况**静默跳过**（`danmaku.py:40-52`；`base.py:41-45`）。
- `is_embed_available` 判据 —— `File.merge_file_ext == "mkv"`（`base.py:41-45`）。
- 登记项 —— `kind="danmaku"`、`title="弹幕"`、`language` 空（`danmaku.py:48-52`）。
- 开关 —— `embed_danmaku`（默认 False）、`delete_danmaku_after_embed`（默认 False）（`config.py:370-371`）；嵌入后删除源文件见 `merger.py:409-423`。

### 8.2 字幕
- 支持 **5 种**格式：SRT / LRC / TXT / ASS / JSON（`enum.py:46-51`）；**默认 ASS**（`config.py:374`）；GUI 选项 `src/gui/component/setting/card.py:287`。

- 语言筛选 —— `subtitle_language.download_specified` 为真时按 `lan` 精确匹配 `specified_language`，否则全下（`subtitles.py:170-177`；`config.py:128-131`）。

- AI 字幕识别 —— `lan` 的 `ai-` 前缀（`AI_LANGUAGE_PREFIX`，`subtitles.py:13-14,102-103`）。
- 字幕轨标题 —— AI 字幕加后缀，整句模板 `{name} (AI Generated)`={name}（AI 生成）（`translator.py:342-347`；`zh_CN.ts:3911`）；人工字幕用 `lan_doc`（`subtitles.py:97-105`）。
- 文件名 —— `<name>.字幕.<lan>.<ext>`，`lan` 为 B站原始语言码（如 `ai-zh`、`zh-Hant`）（`subtitles.py:78`）。
- 各格式写出内容 ——
  - SRT —— 序号 + `HH:MM:SS,mmm --> HH:MM:SS,mmm` + 正文（`subtitles.py:121-133`；`time.py:51-67`）
  - LRC —— `[mm:ss.xx]内容`（`subtitles.py:135-147`）
  - TXT —— 纯文本逐行（`subtitles.py:149-156`）
  - ASS —— `SubtitlesASS`（`subtitles.py:158-161`）
  - JSON —— 原始 `body` 结构，indent=2（`subtitles.py:163-164`）
- ASS 样式行字段 —— 字体/字号/主色/次色/描边色/背景色/粗斜下删/ScaleX100 ScaleY100/Spacing0 Angle0/BorderStyle1/Outline/Shadow/Alignment/MarginL/MarginR/MarginV/Encoding1（`file/subtitle_ass.py:44-70`）。
- ASS 默认样式 —— 黑体 36、`&H00FFFFFF`/`&H000000FF`/`H00000000`/`H00000000`、margin 10/10/20、1280×720、alignment 2（`config.py:133-163`）。
- ASS 对齐值 1–9 映射 —— `src/util/common/data/subtitles.py:636-646`；GUI `src/gui/dialog/setting/subtitles_style.py:63-84`。
- **混流条件** —— 仅 ASS + `embed_subtitle` 开 + 输出 MKV（`subtitles.py:82-95`；`base.py:41-45`）。
- 语言码归一为 ISO 639-2 三字母（zh→chi、en→eng、ja→jpn…；**表外原样传递，不用 und 兜底**）（`subtitles.py:16-47,107-119`）。

- 有字幕轨时必须显式映射主流，否则默认流选择失效（`command.py:51-54,112-115,141-143`）。
- 轨道排序 —— 字幕轨在弹幕轨之前，且首条字幕轨标为默认；弹幕轨 disposition 置 0（避免打开即显示弹幕）（`merger.py:398-403`；`command.py:67-69`）。

### 8.7 ffmpeg 相关
- 来源三选一 —— `bundled`（默认）/ `system` / `custom`（`enum.py:73-76`；`config.py:400-401`）。
- 内置路径 = 程序工作目录 `/bundle/ffmpeg(.exe)`；工作目录取环境变量 `PYSTAND_HOME` 否则 `Path.cwd()`（`src/util/ffmpeg/__init__.py:51-52`；`src/util/common/io/directory.py:155-160`）。
- 可执行名按平台 —— win32 `ffmpeg.exe`，否则 `ffmpeg`（`ffmpeg/__init__.py:13-18`）。
- 探测逻辑 —— bundled 只看文件是否存在；system 用 `shutil.which()`；custom 只看路径是否存在（**无版本探测、无 ffprobe、无 `-version` 调用**）（`ffmpeg/__init__.py:31-52,71-72,93-99`）。
- 找到后把其所在目录**前插 PATH**，并置 `config.no_ffmpeg_available = False`（`:24-29`）。
- **回退链** —— bundled 失败→system；system 失败→bundled；custom 无效→bundled→system；全都无→`no_ffmpeg_available=True`（`:74-108`）。回退成功会**改写用户设置**（`:80,89,102,105`）。
- 探测时机 —— 显式调用 `init_ffmpeg()`（首屏之后，避免占启动关键路径），只执行一次（`main_window.py:543-547`；`ffmpeg/__init__.py:59-67`）。
- 缺失时弹提示（`main_window.py:298-304`）；设置页选 bundled 但文件缺失时也提示（`src/gui/interface/setting.py:281-292`）。
- 实际执行的命令里可执行文件名**硬编码为 `"ffmpeg"`**，靠上面的 PATH 前插生效（`command.py:85`）。
- 容器格式 mp4/mkv（默认 mp4）；`merge_file_ext` 仅在「音视频合并或分片合并」存在时才赋值（`config.py:363`；`downloader/parse_worker.py:310-319`）。
- 音视频混流 —— `-c:v copy -c:a copy` + `-strict unofficial`（**保留杜比视界 dvcC/dvvC box**）（`command.py:98-106,26-34`）。
- 分片合并 —— `-f concat -safe 0` 读 `lists_<task_id>.txt`（内容 `file 'video_<task_id>_<i>.<ext>'`）（`command.py:127-134`；`merger.py:438-452`）。
- 参数拼接顺序 —— 各输入前置参数 → `-i` → 全局参数 → 输出（`command.py:84-95`）。
- 其它命令 —— m4a→mp3（`libmp3lame -q:a 2`）（`command.py:153-161`）；`fix_mp4_box`（`-c copy -movflags +faststart`）（`:163-171`）但**调用点已被注释掉**（`merger.py:79-81`）。
- 运行期 —— 在 `ffmpeg` 之后插入 `-progress pipe:1 -nostats`（`runner.py:118-128`）；Windows 下 `CREATE_NO_WINDOW`、`stdin=DEVNULL`（`:72-92`）。
- 进度 —— stderr 解析 `Duration:`（多路输入取最长），stdout 解析 `out_time_us=`，百分比**封顶 99**（`runner.py:15-18,188-221`）。
- 终止 —— 子进程 `terminate()`，**绝不用 `QThread.terminate()`**（`runner.py:229-251`）。
- 失败处理 —— stderr 关键词映射到本地化错误（空间不足/权限不足/文件损坏/找不到/无法打开/被占用/无法创建），未命中则用异常文本（`merger.py:277-305`）。
- ⚠ **无自动换容器/降级重试** —— 失败即置 `FFMPEG_FAILED` 并释放并发额度、弹长消息 toast（`merger.py:307-323`）。
- 封面/字幕/章节作为输入的组装顺序约定（字幕必须排在封面之后，因封面输入索引写死）（`command.py:117-119`）。

### 11.9 代理支持
- 代理模式枚举（三态）—— `DISABLED`（不启用代理，始终直连）/ `SYSTEM`（跟随系统代理，环境变量，Windows/macOS 上还包括系统代理设置）/ `MANUAL`（使用程序内手动配置的代理服务器）（`enum.py:63-66`）。
- 代理类型枚举 —— **仅 `HTTP = "http"` 生效；SOCKS4 / SOCKS5 在枚举与实现中均被注释掉，本版本不支持**（`enum.py:68-71`；`src/util/network/proxy.py:42-52`）。
- 代理配置项 —— `proxy_mode`（默认 `SYSTEM`）、`proxy_type`（默认 `HTTP`）、`proxy_server`、`proxy_port`（默认 80）、`proxy_uname`、`proxy_password`（`config.py:403-408`）；`proxy_mode` 改动需重启（`restart = True`）。
- 代理 URL 拼接 —— 有账号密码时 `{protocol}://{uname}:{password}@{server}:{port}`，否则 `{protocol}://{server}:{port}`（`proxy.py:25-29`）；仅 MANUAL 返回代理（`:31-33`）；HTTP 代理同时挂 http 与 https（`:36-40`）。
- 三种模式的应用入口 —— `get_proxy_mounts()`：MANUAL → `get_mounts(Proxy().get_proxies())`；SYSTEM → `get_env_mounts()`；其他 → `None`（直连）（`request.py:160-173`）。
- 手动代理 mounts —— 两个 pattern 都建 `HTTPTransport(proxy=..., retries=5, limits=..., verify=...)`（`request.py:108-119`）。
- **系统代理还原（关键坑）** —— 因为显式传 transport 会绕过 httpx 的环境代理，故手动调 `httpx._utils.get_environment_proxies()` 还原成 mounts（`request.py:121-158`）；`NO_PROXY` 命中项写 `None` 表示回退直连（`:145-147`）；不支持的代理协议容错（单条失败只告警并降级直连）（`:153-157`）。
- 代理应用范围 —— 解析、预览、下载、CDN 探测全部调用同一 `get_proxy_mounts()`（`download_url.py:58`；`downloader.py:945,952-958`）。
- 代理测试 —— `Proxy.set_data()`（强制 MANUAL）+ `NetworkRequestWorker.set_proxies()`，打 `x/web-interface/zone` 拿 IP/地区/ISP（`proxy.py:14-22`；`src/gui/dialog/setting/proxy.py:80-92`）。
- 历史迁移 —— 2.13.0 起由 `proxy_enabled` 开关改为 `proxy_mode` 三态，旧值 `True` 迁移为 `MANUAL`（`config.py:543-546`）。

- 探测专用 client —— 独立于全局 client，`retries = 0`；理由：全局 client 的重试会让单个黑洞节点吃掉约 23s 预算（`:30-63`）；连接数 `max_connections = 64`/`max_keepalive_connections = 16`（`:54`）；**探测不带 Cookie**（鉴权信息全在查询参数里）（`:40-41`）。

### 11.12 线程 / 异步模型
- 全局线程池 —— `pool = QThreadPool.globalInstance()`（未改 `maxThreadCount`，用 Qt 默认值 = CPU 核数）（`src/util/thread/pool.py:7`）；投递 `GlobalThreadPoolTask.run()/run_func()`（异常统一记「后台任务触发异常」）（`:11-25`）。
- 下载分片线程池 —— 每个 Downloader 自建 `QThreadPool()`，`setMaxThreadCount(config.get(config.download_thread))`（`downloader.py:402-403`）。
- 下载 client 连接数 —— `max_connections = max_keepalive_connections = config.get(config.download_thread)`（`downloader.py:942`）；`HTTPTransport(retries = 5)`（`:943`）。
- 合并并发 —— 由下载列表 model 的 `manageConcurrentMerges()` 独立调度，上限硬编码 1（`src/gui/component/download_list/model.py:274-310`）。
- 封面加载线程池 —— 独立 `QThreadPool()`，`setMaxThreadCount(16)`（`src/util/download/cover/manager.py:20-24`）。
- CDN 探测并发 —— `PROBE_CONCURRENCY = 4` × 每次调用独立线程池 8 线程（`download_url.py:15,90`）。
- **任务线程模型** —— `AsyncTask.run(worker)`：为每个 worker 新建 `QThread` + `moveToThread`，登记进 `thread_queue`，`finished` 连接 `quit`/`deleteLater`，线程结束后 `remove_from_queue`（`src/util/thread/async_.py:11,29-50`）。
- **退出收敛** —— `AsyncTask.safe_quit(timeout=3000)`：3000ms 是**所有线程共享的总预算**，先统一 `quit()` 再统一等待；**不做 `terminate()`**（Windows 上会 FAST_FAIL），未退出者留给进程回收并 warning（`async_.py:52-95`）。
- Worker 基类 —— `WorkerBase` 提供 `success()`/`error()`/`finished()` 三信号与空 `run()` 槽（`src/util/thread/worker_base.py:3-13`）。
- **线程调度器** —— `_MainThreadDispatcher`（常驻 GUI 线程的 QObject）把任意可调用对象经信号排队到 GUI 线程；已在 GUI 线程则退化为直连保持同步语义（`src/util/thread/dispatcher.py:9-45`）；入口 `post_to_main_thread()` 与装饰器 `run_in_main_thread()`（`:60-76`）。存在原因见 `:10-21` 注释（`AsyncTask` 的 worker 信号连到局部闭包时是直连，回调整个跑在子线程，碰 Qt 控件/QPixmap/QTimer 不安全）。
- 网络栈预热 —— httpx 导入（~0.3s）与 SSL 上下文构建（~0.5s）放到后台线程（`main.py:525-529`）。

### 11.13 MCP 服务器（AI 客户端接入）
**这是什么** —— 在**本地环回地址**上跑一个 HTTP MCP 服务器，让 AI 客户端调用本程序的解析与下载能力（`src/util/mcp/__init__.py:1-8`）。
- 传输 —— Streamable HTTP，单端点 `POST /mcp`（`mcp/server.py:18`）。
- 协议版本 —— modern `2026-07-28`；兼容 legacy `2025-11-25` / `2025-06-18` / `2025-03-26`（dual-era）（`mcp/protocol.py:17-21`）；modern 与 legacy 差异仅握手方式、请求头校验、`resultType` 三处（`:9-16`）。
- 支持的方法 —— `server/discover`、`initialize`、`ping`、`tools/list`、`tools/call`（`protocol.py:166-205`）；未实现的方法回 HTTP 404 + `-32601`（`:202-205`）。
- 错误码 —— `-32700/-32600/-32601/-32602/-32603` + `-32020`（头不匹配）+ `-32022`（版本不支持）（`:47-53`）。
- **鉴权** —— `Authorization: Bearer <mcp_token>`，用 `secrets.compare_digest` 定长比较防时序侧信道；失败回 401 + `WWW-Authenticate`（`server.py:160-181`）。
- **Origin 校验** —— 非浏览器客户端可不发；一旦存在必须是 `http://localhost*` / `http://127.0.0.1*` / `http://[::1]*`，`null` 一律拒绝（防 DNS rebinding）（`server.py:48-65,110-116`）。
- 请求头与 body 一致性校验 —— `MCP-Protocol-Version`、`Mcp-Method`、`Mcp-Name` 都必须与 body 一致；`Mcp-Name` 支持 `=?base64?…?=` 哨兵解码以承载中文工具名（`server.py:229-285,29-46`）。
- 请求体上限 `MAX_BODY_SIZE = 1MB`，超限回 413（`server.py:21,222-225`）；拒绝前先 drain body（否则 Windows 发 RST，客户端只看到"连接被中止"而看不到 401）（`:183-206`）。
- 每连接一线程、用完即断（`ThreadingHTTPServer` + `close_connection = True`）（`:81-91,320`）；请求线程**非守护**（守护线程被强杀会导致访问违例，实测退出码 0xC0000005）（`:335-343`）；端口复用 `allow_reuse_address = True`（`:332-333`）。
- 退出 —— `stop()` 先 `begin_shutdown()` 让在途跨线程调用立即失败，再 `join(2.0)`（`:438-462`）。

- 工具执行失败走 `isError`（内容错误），不走 JSON-RPC error（`tools/__init__.py:33-40`；`protocol.py:235-238`）。

- 重复下载就地决策 —— 强制 `CONTINUE`（redownload=true）或 `SKIP`，避免 `ALWAYS_ASK` 弹窗在无人值守链路里无限等待（`download.py:359-365`）。
- 嵌入门槛预检 —— `embed_danmaku`/`embed_subtitle` 要求对应格式为 ASS、容器为 MKV、且必须走合并（只下音频时报错）（`download.py:179-220`）。
- 枚举值归一化 —— 折叠空格/`-`/`_` 并大写，故 `hi_res`/`Hi-Res`/`HIRES` 都认（`download.py:21-24`）。
