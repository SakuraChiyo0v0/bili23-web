# bili23-web 界面重设计调研 Spec（B 站官网风 · 响应式）

日期：2026-09-03 · 状态：方向调研，待确认后实施 · 类型：UI/UX 设计规格

---

## 0. 结论先行

当前 `bili23-web` 的 **P0–P4 功能已全部实现并可下载运行**（解析→下载→合并→历史→限速→队列→设置→i18n→Docker 部署全链路闭环）。**问题只在「界面」**：现在用的是最朴素的文本按钮 + 原生表单控件 + 左侧文字导航，和它背后的完整功能不匹配，也没有为手机适配。

本次改动目标是「换皮 + 响应式」，**不动任何后端与下载逻辑**（功能零回归）。设计上**不照抄**桌面版 Bili23 界面，而是**借 B 站官网那套「卡片网格 + 圆角 + 蓝/粉主色 + 移动优先」的观感**，做一个服务于「下载管理」的清爽 Web 界面，同时保证 **电脑宽屏 / 手机窄屏** 都能舒服使用。

## 2. 现状问题排查（附观察）

对照真实当前页面（`http://localhost:8787`）：

- **没有主色**：按钮是灰底灰边，缺少品牌色引导，整体偏「后台管理表单」而非「可用产品」。
- **输入区简陋**：解析入口是一个大 `textarea` + 两个灰按钮，没有「搜索框 + 主按钮」的强视觉。
- **列表不可扫读**：解析结果用「卡片堆叠」，每项一张封面 + 标题 + 元信息，信息密度低、占屏高。
- **无移动适配**：左侧 170px 文字导航在手机上会挤压内容；窄屏下卡片、表单、表格都会横向溢出或很拥挤。
- **控件原生化**：checkbox / select / 按钮都是浏览器默认样式，不够现代。

## 3. 风格参考：B 站官网设计语言（基于真实截图观察）

用 Chrome headless 抓了 `www.bilibili.com` 桌面（1400×900）与手机（414×896）两版截图，提炼出以下可复用特征：

| 特征 | 观察 | 是否沿用 |
| --- | --- | --- |
| 顶部导航 | 顶部横条：logo（左）→ 横向链接 → 居中大圆角搜索框 → 右侧主按钮 | ✅（移动端折为底部 TabBar） |
| 主色 | 交互与「登录/搜索」用 **B 站蓝 `#00AEEC`**；「投稿」等用 **粉色 `#FB7299`** | ✅（蓝主、粉次） |
| 分类 Chips | 一排圆角胶囊标签（番剧/国创/综艺…），可横向滚动 | ✅（用于解析类型/下载分组/设置分组） |
| 卡片网格 | 视频以「封面 + 时长角标 + 两行标题 + UP/日期 meta」组成卡片，多列栅格，悬浮带阴影 | ✅（解析结果、历史、产物文件都用卡片网格） |
| 圆角与留白 | 卡片大圆角、大留白、柔性灰色表面；白底配浅灰边框 | ✅ |
| 响应式 | 手机端顶部导航变横向滑动、内容变 **2 列卡片**、主区全宽 | ✅（移动优先断点） |

**结论**：不照搬 B 站的导航与内容，只借用它的**配色、卡片、圆角、栅格、移动优先**这层「皮肤」。产品语义（解析/下载/设置）仍是 Bili23 自己的。

## 4. 设计方向

### 4.1 原则

1. **移动优先**：先按手机小屏设计，再向宽屏扩展；触控目标 ≥ 44px。
2. **会话清晰**：用户进来第一眼知道能干嘛 →「粘贴链接 → 解析 → 勾选 → 下载」主线在主界面可见。
3. **卡片化**：视频类内容（解析结果 / 历史 / 产物）统一用「封面卡片网格」；纯信息用表格/列表。
4. **一屏一任务**：主区永远只有一个页面（解析 / 下载 / 设置），导航切换不丢状态。
5. **深浅主题**：沿用 `system/light/dark`，用 CSS 变量承载全部配色。

### 4.2 信息架构（三页 + 导航）

```
桌面：顶部 AppBar（logo / 页面名 / 主题切换）  +  内容区
手机：顶部紧凑 AppBar（logo / 搜索 / 主题）  +  底部 TabBar（解析 / 下载 / 设置）
```

- **解析页（首页）**：大搜索区（多行输入）→「解析」主按钮；下方结果卡片网格（封面 + 时长 + 标题 + UP + 勾选）。
- **下载页**：顶部状态 chips（全部 / 进行中 / 已完成 / 失败）+ 任务卡片列表（进度 + 速度 + ETA + 操作）；再往下「历史」「产物文件」两张卡片。
- **设置页**：分组 chips（行为 / 下载 / 附加 / 命名 / 高级）+ 每组一张表单卡片。

## 5. 设计 Tokens

### 5.1 配色（建议值，落地时可微调）

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--accent`（主蓝） | `#00AEEC` | `#40C6F0` | 主按钮、激活态、链接 |
| `--accent-soft` | `#E6F7FF` | `#123141` | 选中/高亮底 |
| `--brand`（粉） | `#FB7299` | `#F58CA9` | 次强调 / 徽标 / CTA 点缀 |
| `--bg` | `#F6F7F9` | `#0F1115` | 页面背景 |
| `--surface` | `#FFFFFF` | `#181B21` | 卡片/面板 |
| `--surface-2` | `#F1F3F6` | `#20242C` | 分组/输入底 |
| `--border` | `#E4E8ED` | `#28303B` | 分隔线/边框 |
| `--text` | `#1B2026` | `#E7ECF1` | 主文本 |
| `--text-2` | `#59636E` | `#A4ADB8` | 次要文本 |
| `--success` / `--danger` | `#2FA46B` / `#D64541` | `#4EC98A` / `#F0746E` | 语义 |

> 说明：把主色从当前「青绿 teal」换到「B 站蓝」，粉色作次强调，最能传达「B 站感」；危险/成功保持独立语义色不混入品牌色。

### 5.2 其它 Token

- **字体**：`system-ui, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif`；数值/时长用等宽 `ui-monospace` 更对齐。
- **圆角**：卡片 `12px`，按钮 `8–10px`，chips `999px`。
- **间距**：4/8/12/16/24/32 基准；卡片内边距 16px，网格 gap 16px。
- **阴影**：卡片默认 `0 1px 2px rgba(16,24,40,.06)`；hover `0 8px 24px rgba(16,24,40,.12)`。
- **断点**：`<480` 手机 / `≥768` 平板 / `≥1200` 宽屏。

## 6. 响应式策略

| 区块 | 桌面（≥1200） | 平板（768–1199） | 手机（<768） |
| --- | --- | --- | --- |
| 导航 | 顶部 AppBar + 链接 | 顶部 AppBar | 顶部紧凑栏 + 底部 TabBar |
| 解析输入 | 居中大搜索区，多行 | 同上 | 全宽，输入区占首屏 |
| 结果网格 | 4–5 列卡片 | 3 列卡片 | 2 列卡片 |
| 下载任务 | 单列列表（宽），信息横向铺开 | 单列 | 单列，操作区纵向堆叠为触控友好按钮 |
| 设置 | 分组 chips + 卡片 | 同上 | 分组 chips 横向滚动 + 纵向卡片 |
| 弹层/日志 | 内联手风琴 | 内联 | 全屏抽屉 |

## 8. 交互细节（移动端触控友好）

- 所有可点元素 ≥ 44×44px；按钮间距 ≥ 8px。
- 下载操作（暂停/继续/重试/删除/日志）在手机上以「图标 + 文案」小按钮横向排列，避免只靠悬停。
- 日志展开在手机上用**全屏底部分层**，阅读区可滚动，避免内联挤压。
- 勾选/全选提供**明确选中计数**（如「已选 3 项」），避免误操作。
- 解析加载/下载进度用**骨架屏 + 实时 SSE**，不让用户等空白。

---

## 9. 验收标准（本 UI 重设计出口）

1. 桌面 / 平板 / 手机三个断点均无横向溢出，布局不破。
2. 解析入口一眼可见「粘贴链接 + 主按钮」；解析结果以卡片网格呈现并可勾选。
3. 下载页能实时看到进度 / 速度 / ETA，且暂停/继续/重试/删除一键可达。
4. 设置页所有分组可导航、可保存、深浅主题实时切换。
5. 色板换为 B 站蓝/粉后，`pnpm check`（typecheck+test+build）仍全绿，下载功能零回归。
6. 真网冒烟（同 P4 流程）通过：解析→批量→下载→合并→产物可播。

## 10. 风险与待确认

| 项 | 说明 |
| --- | --- |
| 是否彻底放弃青绿主色 | 建议改为 B 站蓝/粉；若你更想保留 teal 可只做「布局+响应式」，主色不变 |
| 移动端是否要底部 TabBar | 默认做（B 站官网移动版也是底部导航）；若你偏好单一顶部栏可去掉 |
| 是否引入视觉资源 | 只内联 SVG 图标，不引字体/图片 CDN，保持 NAS 离线可用 |

**一句话**：功能已齐，就差一套「能打」的皮；按上面这套 B 站风 + 响应式 tokens 重构前端，风险集中在样式层，功能零改动。
